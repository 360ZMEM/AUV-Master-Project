## 2. v1 口径与 v2 实现的关键差异

| 项目 | 当前 PPT 口径 | 应同步为 v2 口径 |
|---|---|---|
| 任务入口 | 已检测目标附近直接 Zig-zag | 先验引导 Search → 磁检测 → Confirm 主动横切 → FWHM → Track |
| 横轴 | 匀速横切隐含为“时间乘速度” | 使用导航位置投影得到局部法向空间坐标 `x`，不依赖匀速假设 |
| 半高定义 | 峰值绝对值的一半 | `B_half = B_bg + 0.5(B_peak-B_bg)`，必须先修正背景 |
| 扫描范围 | 一次固定摆幅 | 以 ±4/±8/±14/±20 m 逐级扩幅，直至包围完整磁峰 |
| 交点 | 原理图中隐含存在 | 显式求左右插值交点；缺少任一侧即拒绝发布 |
| 距离换算 | 固定 `W_x=2z` | `z=κ_M W`，其中场形系数 `κ_M` 必须声明、标定并给出不确定度 |
| 埋深 | 垂向距离直接称为埋深 | `burial = vertical_separation-altitude`，高度误差进入埋深不确定度 |
| 输出 | 一个深度结果 | 同时输出有效性、剖面置信度、垂向距离、埋深及其不确定度 |
| 失败处理 | 未说明 | 不完整双侧覆盖、沿缆漂移过大、模型不一致时进入重捕，不发布深度 |
| 稳定性证据 | 只有理论关系 | 已完成 7 场景 × 4 方法 × 200 种子的 5600 次方法运行 |

PPT 中最需要删除或改写的是“远场偶极子、**匀速横切**与稳定单峰条件下，宽度约为两倍垂向距离”。建议改为：

> 在声明并标定场形模型、使用导航空间坐标且扫描完整覆盖磁峰两侧时，FWHM 可换算垂向距离；整体增益主要改变峰高，但场形失配仍会造成系统偏差。

## 7. 答辩高概率追问与建议回答

### 为什么不用磁场幅值直接反演？

幅值法在源电流、传感器增益和铠装衰减标定准确时可以很准，但未知整体增益会直接变成距离偏差。增益变化场景中，FWHM MAE 为 `0.027 m`，标定幅值反演为 `0.772 m`。因此当前把 FWHM 作为主反演量，幅值作为源强和模型一致性检查。

### FWHM 是否与电流和场模型都无关？

只对整体幅值尺度近似不敏感。宽度到距离仍依赖场形系数 `κ_M`。错误地把单直导线场形按偶极系数换算时，FWHM MAE 达 `2.753 m`。因此必须先标定模型，再谈距离精度。

### 为什么扫描偏心时有效率只有 74%？

因为算法选择拒绝没有完整双侧交点的剖面。已发布结果的 90% 分位误差为 `0.045 m`，且没有误差超过 `0.5 m` 的发布。这里的低有效率体现安全门，而不是随机崩溃。

### 为什么要把 Zig-zag 幅度加到 20 m？

不是固定要求所有任务都扫 20 m，而是本演示中检测中心与真实峰值仍有偏差，前三档没有包围双侧交点，所以逐级扩幅到第四档。无条件放大摆幅会增加沿缆漂移，v2 同时设置法向对准和沿缆范围门。

### 777 点真实数据为什么没有实测埋深？

原记录是自由手持三维运动，用于磁场、位姿和锁相结果的联合几何验证。v2 将其拆成 9 条候选扫描腿，只有 4 条通过运动几何门，0 条具备完整双侧半高交点；缺少同步海床高度和受控导线真值，因此只能证明拒绝路径，不能形成埋深精度。

### 置信度很高是否代表埋深准确？

不代表。剖面置信度评价磁峰是否被包围、交点是否完整和宽度能否稳定测量。PVS 中曾出现约 `0.955` 的剖面置信度但距离偏差 `1.005 m`，原因是场形系数不匹配。模型不确定度和高度不确定度必须单独进入埋深误差棒。

## 8. 为正式答辩建议继续完成的工作

### 必做：受控双侧横切与场形系数留出验证

这是当前证据链最明显、也最值得补的一环。最小实验设计应包括：

- 已知导线或缩比电缆位置，并给出横向中心与垂向距离真值；
- 同步记录 TMR、ADC、二维/三维位姿和传感器离底高度；
- 每条轨迹覆盖磁峰两侧并越过两个半高交点；
- 至少三个垂向距离档，每档执行双向重复横切；
- 用一部分数据标定 `κ_M`，用独立留出数据验证，禁止同一批数据既标定又报告精度；
- 同时报告有效发布率、MAE、90% 分位误差、大误差发布率和拒绝原因。

如果实验条件允许，再改变电流或数字增益，验证 FWHM 宽度对整体幅值尺度的稳定性。答辩价值高于继续增加同源合成场景。

### 必做：形成一段可回放的全链路演示

保存一条 Search → Detection → Confirm → FWHM → Track 的 ROS bag 或等价回放，并同步显示：

- 俯视任务轨迹和状态机阶段；
- 实时 `B(x)`、背景、左右交点和有效性；
- 埋深、不确定度、置信度和拒绝原因；
- 进入 Track 后的横向误差。

答辩时播放 20--30 秒加速视频，静态页面仍使用图 1 和图 2。视频用于说明系统在运行，统计图用于支撑结论，两者不要互相替代。

### 建议做：把模型失配门变成可见诊断量

现有实验已证明错误场形会造成系统偏差。下一步应在诊断输出和答辩备份中明确展示模型身份、`κ_M` 来源、剖面拟合残差及拒绝阈值。这样可以回答“系统如何知道自己用了错误模型”，而不是只在事后解释误差。

### 不建议继续投入的方向

- 不需要继续扩展复杂规划算法；先验走廊规则搜索已经足以支撑论文主线。
- 不要通过无限增大 Zig-zag 幅度追求有效率；应优先保证法向对准、双侧覆盖和沿缆漂移约束。
- 不要继续堆叠同源合成模型下的低 MAE 数字；正式答辩最缺的是受控实物横切与独立标定/验证。
