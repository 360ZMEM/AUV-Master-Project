## 1. 本轮结论

### 1.1 已完成

7. 完成第 1–6 章与附录 A 的确定性迁移、逐章验收和 170 页 A4 联合构建。

### 1.2 本轮不做

- 不把约 15 万字正文一次性机械转换后直接宣称可提交。
- 不覆盖 `thuthesis-example.tex`、`thusetup.tex`、`thubeamer-1.2/main.tex` 等上游示例入口。
- 不在 `thuthesis` 当前 261 个 CRLF 伪改动之上继续堆叠正文。

- 不把尚未完成的硬件实验通过排版包装成已完成结果。

### 1.3 总体决策

采用“一份内容事实、两种出版视图、一个资产库”的结构：

| 层级 | 单一事实源 | 目标 |
|---|---|---|
| 正文内容 | `docs/thesis/paper/*.md` | 论文叙事、公式、引用、图注和结论边界 |
| 参考文献 | `毕业设计写作文档/参考文献/文献引用信息/references.bib` | 论文与答辩共享引用键 |

在章节完成迁移验收前，Markdown 是内容事实源，LaTeX 是受控出版目标；禁止两侧独立修改同一段事实。全章迁移并经逐段对照后，才可为该章执行一次明确的事实源切换。

### 2.2 `thuthesis`

- 仓库内类版本：ThuThesis 7.6.0，类日期 2025-03-28。
- 当前分支基于提交 `f458847`，已有作者、标题和日期等本地信息。
- 强制命令 `gtimeout 180 latexmk -g thuthesis-example` 实测成功，生成 30 页 A4 PDF。
- 当前入口为：

```latex
\documentclass[
  degree=master,
  degree-type=professional,
  fontset=windows
]{thuthesis}
```

- `fontset=windows` 在本机依赖 Microsoft Word 应用资源中的 SimSun/SimHei/FangSong。当前能编译，但不具备 Linux/干净 macOS 环境可移植性。
- `discipline` / `discipline*` 对专业学位已被模板标记为弃用，应改用 `professional-field` / `professional-field*`。
- 当前 `data/chap01.tex` 至 `chap04.tex` 仍是模板示例正文，摘要、符号表、致谢等也大多是示例内容。
- 当前主文件只装配 4 章，尚无第 5、6 章和本项目附录映射。
- 独立 Git 仓库有 261 个“整文件删除再增加”式改动；文件检测表明主要是 LF → CRLF。正文迁移前必须先建立干净迁移分支并处理行尾策略，否则后续 diff 无法审阅。

论文最终建议：

```latex
\documentclass[
  degree=master,
  degree-type=professional,
  fontset=fandol
]{thuthesis}
```

`fandol` 用于 macOS/Linux 持续编译基线。若学校终稿明确要求 Windows 字体，则在终稿发布流水线增加 `fontset=windows` 构建，不把开发环境绑定到 Word 应用字体。

### 2.3 `thubeamer-1.2`

- 模板版本：1.2，日期 2023-11-27。
- 目录本身不是独立 Git 仓库，目前由根仓库视为未跟踪目录。
- 默认画幅是 4:3，不适合作为当前答辩主入口。
- 官方 `make beamer` 使用 PdfLaTeX，实测失败：
  - CTeX 的 mac 字体集在 PdfLaTeX 模式不可用；
  - 最终因缺少位图字体 `uniyou73` 无法输出 PDF。
- 改用 XeLaTeX 后，默认 mac 字体集继续因 macOS 当前没有 `STXihei` 失败。
- 在加载主题前传入：

```latex
\PassOptionsToPackage{fontset=fandol}{ctex}
```

并使用 XeLaTeX 后，示例实测成功，生成 16 页 PDF。
- 主题内部无条件加载 `natbib`，答辩端不应直接叠加 BibLaTeX；答辩使用 BibTeX 即可，引用数据库仍由同一个 canonical `.bib` 受控生成。
- 主题同时加载 PSTricks、multimedia、algorithm 等大量宏包。项目入口应尽量少用这些旧能力，避免把答辩构建绑定到不必要的复杂依赖。

答辩入口必须从 16:9 和跨平台字体开始：

```latex
\PassOptionsToPackage{fontset=fandol}{ctex}
\documentclass[aspectratio=169,10pt]{beamer}
\usetheme[thupurple]{thubeamer}
```

## 5. 首轮格式化规则

### 5.1 标题层级

| Markdown | LaTeX |
|---|---|
| `# 第 N 章：标题` | `\chapter{标题}`，不保留手写章号 |
| `## N.x 标题` | `\section{标题}` |
| `### N.x.y 标题` | `\subsection{标题}` |
| `#### 标题` | 优先 `\subsubsection{标题}`；过细时改为 `\paragraph{标题}` |
| `## 参考文献` | 删除，由全书统一生成 |

章节号、图号、表号、公式号全部交给 LaTeX 自动维护，正文只使用 `\ref`、`\eqref` 和 `\autoref` 风格交叉引用。

### 5.2 图片与 caption

当前 Markdown 已采用“图片行 + 字符串化 caption + `\label`”结构，例如：

```markdown
![不确定性流向图](../figures/architecture/auv_v2_uncertainty_highway.png)

**图 3-1　感知不确定性……** \label{fig:ch03-uncertainty-highway}
```

迁移时必须合并为一个不可拆分的 `figure` 环境：

```latex
\begin{figure}[htbp]
  \centering
  \includegraphics[width=\linewidth]
    {architecture/auv_v2_uncertainty_highway.pdf}
  \caption{感知不确定性从物理扰动到安全执行的传递链路}
  \label{fig:ch03-uncertainty-highway}
\end{figure}
```

规则：

1. caption 中不手写“图 N-N”。
2. `\label` 必须紧跟 `\caption`。
3. 长解释从 caption 移到正文或 `\caption*`，避免图目录变成整段文字。
4. A4 论文优先 PDF 矢量图；照片、界面截图和确为栅格的热图保留 PNG/JPG。
5. Beamer 不显示论文式长 caption，改为页内一句结论或图下注释。

### 5.3 表格

- 普通结果表使用 `booktabs`。
- 自适应列宽使用 `tabularx`。
- 跨页表使用 `longtable`。
- 含统计口径、样本量和边界的表使用 `threeparttable`。
- 单位优先由 `siunitx` 管理，不在每个单元格重复拼接。
- Markdown 管道表不能不经检查直接接受 Pandoc 默认输出；宽表必须逐表决定横排、拆表或移入附录。

### 5.4 公式与代码

- `$$...$$` 转为 `equation`、`align`、`aligned` 或 `cases`。
- 需要引用的公式补稳定标签，如 `eq:ch04-uampc-cost`。
- 第 4 章多个 fenced block 实际承载公式或状态定义，不能转换成代码清单。
- 行内反引号按语义分流：
  - 变量/数学量改为数学模式；
  - ROS2 topic、文件名和代码标识使用 `\texttt{}`；
  - 路径较长时使用 `\path{}`。
- 代码清单使用 `listings`，不把 `minted` 作为本轮依赖。

### 5.5 引用

- 论文采用 XeLaTeX + BibLaTeX + Biber + `gb7714-2015`。
- 答辩因主题内部固定加载 `natbib`，采用 BibTeX；只列答辩实际引用的少量文献。
- 所有引用键保持当前 `\cite{key}` 不变。
- 当前 6 章实际使用约 54 个引用键，均能在 83 条 canonical 文献库中命中；探查中唯一“缺失”的 `key` 来自装配注释里的字面示例，不是真实引用。
- 各 Markdown 文件尾部的“LaTeX 装配说明”在迁移后删除，避免字面 `\cite{key}` 干扰检查。

论文端建议配置：

```latex
\usepackage[
  backend=biber,
  style=gb7714-2015,
  sorting=none
]{biblatex}
\addbibresource{ref/auv-references.bib}
```

### 5.6 草稿标记

当前正文仍有 TODO、表格占位符、实验待补和“尚未执行”段落。迁移时分三类：

| 类型 | 处理 |
|---|---|
| 可以在正式论文诚实保留的局限 | 改写为正文中的“证据边界/研究局限” |
| 必须在提交前补齐的内容 | 用统一 draft 宏标记，并进入阻断清单 |
| 仅为写作过程说明 | 不进入 LaTeX 正文 |

终稿构建必须开启“零草稿标记”门禁；存在 `TODO`、`占位符`、`待补`、未解析引用或未解析交叉引用时构建不算通过。

## 7. Beamer 叙事与强调规则

### 7.1 主线

推荐 14–18 页主答辩，加独立 backup：

| 页序 | 目的 | 主视觉 |
|---|---|---|
| 1 | 题目与一句话命题 | 海缆巡检任务 + 核心命题 |
| 2 | 工程问题为何困难 | 海底环境、感知不确定性、欠驱动与安全约束 |
| 3 | 现有方法缺口 | “状态有了，但系统不知道自己有多不确定” |
| 4 | 总体方案 | 技术路线或双脑异步架构 |
| 5 | 创新链总览 | 不确定性 Highway |
| 6 | 感知侧机制 | ES-EKF、动态 R、置信度输出 |
| 7 | 感知侧证据 | 多场景/多种子结果，不堆完整表 |
| 8 | 决策安全机制 | BT + 分层守卫 + PC104 本地覆盖 |
| 9 | 控制侧机制 | UA-MPC 的置信度—权重映射 |
| 10 | 主消融结果 | 一图一结论，明确优势成立条件 |
| 11 | 负结果与根因 | 失败曲线 + 根因定位 |
| 12 | 修复与闭环恢复 | 修复前后对照与验收裕度 |
| 13 | 端到端证据阶梯 | clean prior → 失效边界 → 6-DOF 恢复 |
| 14 | 工程部署边界 | 已完成、未完成、不能声称 |
| 15 | 贡献总结 | 机制、系统、证据三类贡献 |
| 16 | 结论与展望 | 回答开头问题 |

### 7.2 单页信息密度

每页只允许一个中心判断：

```text
结论句（不超过两行）
    ↓
一张主图或一个对照表
    ↓
一个数字 + 一个适用边界
```

禁止：

- 从论文复制整段文字。
- 一页放 4 张以上完整结果图。
- 把 8 pt 字号当作解决拥挤的方法。
- 用绿色“PASS”覆盖 NOT READY、`n=1` 或代理场景边界。
- 在主答辩页展示文件路径、运行命令和大段参数表；这些进入 backup。

### 7.3 视觉强调

- 主色沿用清华紫。
- 绿色只表示经定义口径通过的结果。
- 橙色表示边界、风险和待补证据。
- 红色只表示失败点或安全触发，不用于大面积背景。
- 机制图用“输入扰动 → 不确定性流转 → 决策/控制动作”左到右组织。
- 结果页优先高信息密度时序曲线，并对关键窗口加局部放大或半透明验收带。
- 结论不要只靠颜色，必须同时有文字、符号或线型区分，保证黑白打印和色觉可访问性。

| Matplotlib 折线/散点/柱图 | 生成脚本同次输出 `.pdf` + `.png` |
| GUI/视频末帧/真实照片 | PNG 或 JPG，保持原生像素 |
| 多面板结果 | 优先由源脚本重新排版，不用截图拼接 |

禁止把 PNG 直接封装进 PDF 后称为矢量图。

### 8.3 Beamer 图变种

只有高密度图需要独立 slide 变种，命名建议：

```text
<stem>_slide_169.pdf
<stem>_slide_169.png
```

slide 变种必须从同一数据或同一 `.drawio` 源生成，允许：

- 放大字体和线宽；
- 删除论文图中可由口述替代的次要标签；
- 改为 16:9 视觉层次；
- 高亮一个关键窗口；
- 把四面板拆成连续两页。

不允许修改数据、坐标范围或验收阈值来制造更强优势。

| 资产 | 所有者 | 交接物 |
|---|---|---|
| 实验原始数据、重跑与 Matplotlib 图 | Linux 侧 | 图片、`_SOURCE.md`、manifest、命令、样本量 |
| draw.io 架构图及导出 | macOS 侧 | `.drawio/.png/.svg/.drawio.png`，入选图增加 `.pdf` |
| 论文 LaTeX 排版 | macOS/通用出版侧 | 只消费已确认资产，不重算实验 |
| Beamer slide 变种 | macOS 侧牵头，Linux 侧核对数据 | 同源变种 + 来源映射 |

### 8.5 Linux → macOS 图像交接

Linux 侧每次更新实验图时必须同时提交：

1. 最终图片；
2. 同目录 `_SOURCE.md` 或 manifest；
3. 源 run、生成脚本、完整命令、样本量/seed、关键配置；
4. 数据口径或结论变化说明；
5. 正文中受影响的图标签。

macOS 侧接收后：

1. 校验图片路径与来源记录；
2. 对照正文 caption 和结论；
3. 判断是否需要 PDF 或 `_slide_169` 变种；
4. 编译论文与答辩；
5. 不从 `/auv_data` 私自复制无来源图片覆盖仓库版本。

并行协作以 Git 提交/分支为交接单元，不对两个正在修改的工作树做裸 `rsync --delete`。
