# LaTeX 迁移与编译踩坑总结

> 日期：2026-08-07
>
> 范围：canonical Markdown 第 1–6 章及附录 A 向 ThuThesis 7.6.0 的迁移，以及 ThuBeamer 1.2 的 macOS 编译基线
>
> 目的：记录 F0–F3 已实际遇到的问题、根因、修复和防回归方法。后续迁移、换机或发布审计应先读本文，不再重复踩坑。

## 1. 当前稳定基线

### 1.1 单一事实源

```text
正文：
docs/thesis/paper/*.md

文献：
毕业设计写作文档/参考文献/文献引用信息/references.bib

图片：
docs/thesis/figures/

论文出版视图：
thuthesis/

答辩出版视图：
thubeamer-1.2/
```

在事实源正式切换前，不独立修改 `thuthesis/data/auv-chap*.tex`。正文修改先进入 Markdown，再运行生成器。

### 1.2 推荐命令

论文构建并保留可预览 PDF：

```bash
cd thuthesis
gtimeout 300 make preview-auv-thesis
```

该目标依次执行章节新鲜度检查、文献暂存检查、XeLaTeX/Biber 构建和辅助文件清理，最终保留 `auv-thesis.pdf`。

仅重新构建、不清理：

```bash
gtimeout 300 make auv-thesis
```

仅清理辅助文件、保留 PDF：

```bash
gtimeout 60 make clean-auv-thesis
```

连 PDF 一起删除：

```bash
gtimeout 60 make distclean-auv-thesis
```

答辩构建：

```bash
cd thubeamer-1.2
gtimeout 240 make defense
```

## 2. 环境与模板问题

### 2.1 必须先按操作系统分流

**现象**：同一仓库在 Linux 与 macOS 上具备的工具、字体和 ROS2 环境不同。

**根因**：Linux 侧承担仿真和正文主体；macOS 侧承担出版装配、浏览器、GUI 和 draw.io。

**处理**：每次进入先执行 `uname`。Darwin 读取 `AGENTS_macwin.md`，Linux 读取 `AGENTS_linux.md`。

### 2.2 ThuBeamer 默认 PdfLaTeX 不可用

**现象**：官方 `make beamer` 在 macOS 上因 CTeX 字体集和位图字体 `uniyou73` 失败。

**根因**：模板默认走 PdfLaTeX，且依赖当前系统不存在的字体。

**修复**：

```latex
\PassOptionsToPackage{fontset=fandol}{ctex}
\documentclass[aspectratio=169,10pt]{beamer}
```

项目入口固定 XeLaTeX + Fandol，不把官方 `make beamer` 当作 macOS 构建入口。

### 2.3 XeLaTeX 默认 mac 字体仍可能失败

**现象**：切到 XeLaTeX 后仍报缺少 `STXihei`。

**根因**：CTeX 默认 mac 字体集依赖本机字体，不具备干净环境可移植性。

**修复**：论文和答辩均固定 `fontset=fandol`。若学校终稿要求 Windows 字体，只在最终发布流水线增加专门构建，不污染日常开发基线。

### 2.4 ThuThesis 专业学位字段已弃用

**现象**：模板警告 `discipline` / `discipline*` 对专业学位已弃用。

**修复**：使用 `professional-field` / `professional-field*`。中文、英文专业名称和提交日期仍须在终稿前由作者按学校口径确认。

### 2.5 CRLF 造成整仓伪改动

**现象**：ThuThesis 独立仓库出现 261 个“整文件删除再新增”式 diff。

**根因**：Windows CRLF 与仓库 LF 基线冲突，并非真实内容改动。

**修复**：

1. 建立独立迁移分支；
2. 用 `.gitattributes` 固化 LF；
3. 先归一化行尾，再迁移正文；
4. 保留作者原有真实修改，不用 `git reset --hard` 覆盖。

## 3. 文献链路问题

### 3.1 论文与答辩不能强行共用同一后端

**现象**：ThuBeamer 主题内部固定加载 `natbib`，直接叠加 BibLaTeX 会冲突。

**处理**：

- 论文：XeLaTeX + BibLaTeX + Biber + `gb7714-2015`；
- 答辩：XeLaTeX + BibTeX + 模板 `thubeamer` 样式；
- 两者共享引用键，但分别消费由 canonical 文献库确定性生成的暂存副本。

### 3.2 传统 BibTeX 会误读注释与 `@online`

**现象**：Beamer BibTeX 解析 canonical `.bib` 失败。

**根因**：

- `%` 注释中的 `@` 可能被传统 BibTeX 当作条目起点；
- `@online` 对传统 BibTeX 兼容性不足。

**修复**：`tools/sync_latex_references.py` 为 Beamer 副本删除 `%` 注释，并把 `@online` 映射为 `@misc`；canonical 文献库不改。

### 3.3 第一轮 LaTeX 的 undefined warning 不代表最终失败

**现象**：干净构建第一轮出现大量 undefined citation/reference。

**根因**：此时 `.aux/.bbl` 尚未生成，是正常的多轮编译中间态。

**判据**：只审计 LaTeXmk 最终轮次和最终 `.log`。最终日志不得含：

```text
Citation ... undefined
Reference ... undefined
There were undefined references
Missing character
Overfull \hbox
```

## 4. Markdown 到 LaTeX 的结构问题

### 4.1 不能把 Pandoc 输出直接当终稿

**现象**：标题号重复、图片 caption 分离、表格无标签、代码块语义错误。

**根因**：canonical Markdown 同时包含人工章号、Raw TeX、图片后置 caption 和不同语义的 fenced block。

**修复**：使用 `tools/migrate_thesis_chapters.py` 做受控预处理、Pandoc 转换和后处理，并用 `--check` 阻止陈旧章节参与构建。

### 4.2 手工章号与 LaTeX 自动编号重复

**现象**：生成“第 2 章 2 系统设计”一类重复编号。

**修复**：预处理时剥离 Markdown 标题中的 `1.2.3` / `A.1` 前缀，由 LaTeX 自动编号；稳定标签由生成器产生。

### 4.3 图片、caption 与 label 必须合并

**现象**：Pandoc 把图片和下一行 caption 分成两个对象，caption 重复或 label 丢失。

**修复**：转换前识别“图片行 + caption 行 + `\label`”，合并成一个 figure；caption 不手写图号，`\label` 紧跟 `\caption`。

### 4.4 第 4 章 fenced block 实际是公式

**现象**：10 个无语言 fenced block若按默认规则会变成代码清单。

**根因**：这些块实际承载状态向量、动力学、代价函数和置信度权重公式。

**修复**：按出现顺序显式映射到 10 个带稳定标签的 `equation/aligned` 环境，并对块数量设门禁。

### 4.5 附录 fenced block 才是真正的 Bash

**现象**：多行 Bash 行尾反斜杠使 Pandoc 在 `lstlisting` 后重复输出一份被转义的命令。

**根因**：直接把 raw `lstlisting` 放入 Pandoc 输入时，行尾 `\` 干扰 raw-TeX 边界解析。

**修复**：转换前用唯一哨兵替代代码块，Pandoc 完成正文转换后再注入原始 `lstlisting`。必须检查 begin/end 数量相等且命令只出现一次。

### 4.6 Pandoc 会误解析连续的 `图~\ref`

**现象**：

```latex
图\textsubscript{\ref{...}所示；...图}\ref{...}
```

**根因**：一句中的两个 `~\ref` 被 Pandoc 当作下标边界。

**修复**：Pandoc 前暂时改为 `\nobreakspace{}\ref`，转换后恢复为 `~\ref`。该规则曾同步更新第 1–3 章生成目标哈希，但 canonical 内容未变。

### 4.7 不要全局启用 Pandoc syntax highlighting

**现象**：加入 `--syntax-highlighting=idiomatic` 后，正文行内代码被改成 `\passthrough{\lstinline!...!}`，导致旧章大量无意义变化。

**修复**：撤销全局高亮参数；附录代码块由生成器直接生成 `lstlisting`。

## 5. 表格、字体与断行问题

### 5.1 宽表不能靠全局缩字号掩盖

**现象**：第 5 章 8 列控制消融表中的 `0.0038±0.0004` 溢出。

**无效尝试**：在 `longtable` 外包 `\scriptsize`，内部表格仍恢复字号。

**有效修复**：在 `±` 前加入可断行点，使均值和标准差能在窄列中自然换行。优先增加语义断点，不修改页边距或全章字号。

### 5.2 等宽字体缺少数学字符

**现象**：TeX Gyre Cursor 缺少 `∈`，以及表格中的 `ψ_cmd ∈ [...]` 出现 missing character。

**修复**：数学关系转为数学模式，不把 `∈/≤/≥/ψ/Δ` 留在 `\texttt{}` 中。

### 5.3 勾叉字符可能缺字

**现象**：正文中的 `✓/✗` 在正文字体中缺字。

**修复**：确定性转换为 `\(\checkmark\)` 与 `\(\times\)`，同时保留文字状态，不能只靠颜色或符号表达通过/失败。

### 5.4 长路径和代码标识会产生 Overfull

**现象**：YAML 文件名、ROS2 topic、配置键、CamelCase 标识和 Linux 路径越过表格列或页边界。

**修复策略**：

- 路径优先 `\path{}`；
- 下划线、斜杠、点号、等号和 CamelCase 边界后加 `\allowbreak{}`；
- 窄表中的 YAML 标识可局部使用 `\small`；
- 不在生成后的 `.tex` 手工插断点，应修生成器。

### 5.5 `longtable` 首轮列宽变化是中间态

**现象**：日志提示 `Column widths have changed`。

**根因**：跨页表需要第二轮才能稳定列宽。

**处理**：交给 LaTeXmk 自动重跑；若最终轮仍有警告，再检查表格结构。

## 6. 浮动体与视觉验收问题

### 6.1 图片可能漂到下一节

**现象**：图跨过下一节标题，导致阅读顺序错误。

**修复**：统一 `\begin{figure}[htbp]`，并在每个 figure 后加入 `\FloatBarrier`。不要用大量 `[H]` 强行固定所有图片。

### 6.2 日志通过不等于版面通过

每章至少抽查：

1. 章首页；
2. 最宽表；
3. 最长公式；
4. 高密度图片页；
5. 明确的负结果/边界页；
6. 附录长路径和代码清单。

用 `pdftotext -layout` 定位物理页，再用 `pdftoppm` 导出工作区内 PNG 检查。视觉工具不能读取工作区外 `/tmp` 图片。

### 6.3 负结果不能被排版弱化

第 5 章必须保持可见：

- `n=1`、单种子和多种子边界；
- NOT READY / FAIL；
- 窗口内通过与全程不通过的差异；
- 直角折弯上 LOS 优于 MPC；
- 重度 DVL 丢包下 UA-MPC 不再有优势；
- 数字孪生、部署接口成立与真机验收之间的层级差异。

## 7. 构建、清理与 Git 问题

### 7.1 `latexmk -C` 会删除 PDF

**现象**：每次验收清理后无法随时预览上一次 PDF。

**修复后的目标**：

- `clean-auv-thesis`：`latexmk -c`，清辅助文件、保留 PDF；
- `preview-auv-thesis`：构建后调用上述清理，默认保留可预览 PDF；
- `distclean-auv-thesis`：显式删除 PDF；
- `cleanall/distclean`：模板级全量清理，日常不要误用。

### 7.2 根仓库与 `thuthesis` 是两个 Git 视角

**现象**：根仓库显示 `thuthesis/` 为未跟踪目录，但 `thuthesis` 内部又有自己的分支和状态。

**处理**：审计时分别运行根仓库和 `thuthesis` 内部的 `git status`；不要把一个仓库的结论套到另一个仓库。

### 7.3 工作树很脏时不能回滚无关改动

本项目同时存在 Linux 实验、图片生成、论文正文和出版装配改动。只修改本任务文件；不使用 `git reset --hard`、`git checkout --` 或裸 `rsync --delete` 清理他人工作。

### 7.4 Shell 命令必须有超时

macOS 上 Electron、PDF、深层搜索和网络命令可能挂起。所有耗时命令使用：

```bash
gtimeout <秒> <命令>
```

若 shell 初始化导致 `gtimeout` 找不到，可使用 `/opt/homebrew/bin/gtimeout` 或改用 Python 标准库读取日志。复杂中文递归搜索应避免全仓执行。

## 8. 发布前最小门禁

```bash
python3 tools/migrate_thesis_chapters.py --check
python3 tools/sync_latex_references.py --check
python3 -m py_compile \
  tools/migrate_thesis_chapters.py \
  tools/sync_latex_references.py

cd thuthesis
gtimeout 300 make preview-auv-thesis
```

验收要求：

- 第 1–6 章与附录全部 `OK`；
- 文献暂存哈希匹配；
- label 全局唯一；
- 无迁移占位章节；
- 最终日志无未解析引用、缺字和 Overfull；
- PDF 为 A4 且可打开；
- 摘要、符号表、目录、图表目录、正文、文献和附录均存在；
- 清理后 PDF 保留，辅助文件清空。

## 9. 核心经验

1. Markdown 是事实源，LaTeX 是确定性出版视图；修规则，不手补生成物。
2. 编译成功只是第一层，最终日志和关键页面视觉验收缺一不可。
3. 宽表与长标识优先增加语义断点，不用全局缩字号掩盖问题。
4. 论文结论强度不得超过证据等级；排版不能隐藏负结果。
5. 清理目标必须分级：日常保留 PDF，只有显式 distclean 才删除 PDF。
