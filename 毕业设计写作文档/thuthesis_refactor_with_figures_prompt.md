## 2. 本次最重要的正文政策：写成立的内容，待办放到独立 Markdown

我不希望正文继续充斥：
“尚未验证”“后续待补”“不能证明”“证据缺口”“原始记录还没归档”等工程审计语言。

请采取下面的规则。

### 2.1 不存在或未完成分析的实验，不在正文预告

例如偶极子、电缆屏蔽、平台干扰对照：
- 仓库没有材料：不创建该实验的正文小节。
- 有原始数据但尚未分析：不填写结果、不猜测结论、不放空表。
- 只有实验设想：留在项目记录中，不以“已开展”进入正文。
- 理论和设计有依据：可以保留相应模型与设计，不必附带一长段“该实验尚未完成”。

这些情况统一记录到独立的 `thesis_evidence_backlog.md`，包括未来应插入的位置。

不要为了凑齐建议目录创建空小节、占位图片、“待补”表格或编译进 PDF 的 TODO。

### 2.2 区分项目待办与结论成立条件

可以外移的是：
- 缺少哪个实验、哪个文件尚未归档。
- 哪些数据待分析、下一步准备运行哪个脚本。
- 历史版本争议、人工确认项和详细审计记录。
- 重复出现的“尚不能替代完整海试”等免责声明。

不能外移到导致正文误导的是：
- 结果来自仿真、回放、台架还是真实整艇。
- 实验样本与独立运行次数。
- FWHM 所用模型与几何假设。
- ADC 短接、积分时间、频率和带宽条件。
- PC104 测试的零执行量状态。
- 恢复实验所采用的场景几何重配。
- 会改变结论方向的负结果、比较条件与代价。

请把这些条件自然写入实验设置、图题、表头或结果句，不要再反复用“不能证明……”进行防御式说明。

目标是：正文可独立、准确地被阅读；项目待办与审计细节在正文之外维护。

### 2.3 建议的写法

不推荐：
“ADC 达到 0.0230 nT，但不证明整机精度，也不证明海缆定位能力，且还有温漂和屏蔽实验没有完成。”

推荐在来源一致时写：
“在指定采样、超采样及 1 s、45 Hz 相干解调条件下，短接 ADC 子链的等效磁噪声为 0.0230 nT 矢量 RMS。”

温漂、完整传感器链和整艇测试待办记入 Markdown。

不推荐：
“系统已经解决先验畸变恢复问题。”

推荐在来源一致时写：
“在满足磁观测几何前提的六自由度仿真中，在线修正实现了规定巡检窗口内的恢复。”

具体场景重配条件应在该实验设置中清楚给出，而不是藏入外部记录。

以上数值只是现有底稿中的参照；最终必须核对当前仓库的结果来源。

### 2.4 不要为了“少说边界”删除重要负结果

例如 UA-MPC 控制平滑改善而横向 RMSE 未系统改善，是实验发现的一部分，不是可以删除的项目待办。

正文应写清收益与代价；详细失败日志、运行编号和排查过程可以外移。

已有结果若无法追溯或与另一版本矛盾，不要选择更漂亮的一组，不要自行平均或拼接。保留可支持的定性内容，将有争议的具体断言移出正式结论，并在 Markdown 中保存原文、位置、原因和待确认事项。

## 3. 用研究问题组织论文，不用器件名和实验日期组织论文

整篇论文以四个问题为主线：

A. 怎样从弱磁海缆和载体观测中形成有效的几何信息？
B. 怎样评价、传播和使用这些观测的不确定性？
C. 当观测退化或接口失效时，怎样进行任务决策与安全执行？
D. 以上设计分别得到什么层级的实验支持？

工程细节必须挂到它支持的研究问题上：
- 电缆磁场与铠装模型：说明被测对象及几何观测的物理前提。
- 隔离供电、接地、布局及平台干扰屏蔽：保证测量输入的可用性。
- TMR、ADC、超采样与 DLIA：形成有依据的采集和信号处理链。
- Zig-zag、峰值与 FWHM：利用主动运动构造几何观测。
- 时间同步、ES-EKF、NIS、自适应 R：形成状态与不确定性输出。
- 行为树、授权、UA-MPC、CBF：把不确定性转化为行为和控制约束。
- Jetson、PC104、协议与上位机：承载计算、执行、授权和故障处置。
- 仿真、台架、回放和实物子链：为上述命题提供不同性质的证据。

不是每个节点都叫“创新”。器件、成熟算法、工程设计、方法贡献和实验发现必须区分。

保留已有术语及研究事实，不为凑出整齐的贡献树而改变实际实现。

## 5. 方法与实验的对应关系必须建立，但不必编译一张巨大审计表

在重构记录中建立映射：
研究问题 → 方法段落/label → 验证命题 → 实验段落/label → 图表/数据 → 当前结论。

正文在适当位置采用简洁交叉引用，让读者知道哪里提出方法、哪里提供检验。

每项重要实验至少应回答：
1. 检验前面哪一项设计或假设？
2. 测量条件、基线和自变量是什么？
3. 比較与评价指标是什么？
4. 结果支持怎样的解释？

不必在每项实验末尾机械增加“支持/不支持/下一步”三栏。用自然的学术语言表达，将未完成任务留到外部记录。

重要图表、公式、方法和实验各自保留一个主要呈现位置。其他章节引用，不整段复制。

## 6. 对偶极子、屏蔽和新台架数据的特别规定

我已说明部分偶极子、电缆屏蔽实验有原始数据，但尚未完成分析，也可能尚未进入当前仓库。

请先盘点，不要假定数据一定存在，也不要认定它们已得出结论。

分类处理：
- 未发现文件：外部记录为“当前仓库未定位”，不要写成“实验未开展”。
- 找到原始数据：登记位置、工况、元数据与分析状态；当前不填入结果章。
- 找到既有分析及报告：核对来源与可复现性后，纳入相应小节。
- 只有部分可支持结果：只写这部分，不补全不存在的实验矩阵。

本轮默认不负责完成一项新的科学分析。不要为了让论文看起来完整，临时拟合出一组漂亮曲线就把它当正式结果。

必须严格区分：
A. 在电缆/目标源上包覆材料，用于研究目标场的幅相或几何变化。
B. 在平台干扰源附近屏蔽，用于研究背景干扰抑制。

二者不能共用结论。

同样，直导线复 I/Q 拟合、偶极子模型、三相螺旋模型与 FWHM 条件分别是什么，应按现有证据区分。不能用一个直导线拟合结果证明所有磁源模型或全部埋深反演关系。

已有“0.04 mm 等效”“25%–35% 衰减”“>24 dB 抑制”“供电纹波 <15 μV”等强断言，只在核对当前来源和条件后使用。找不到支撑时，保留有根据的设计/模型内容，移出无来源的效果数字，并在外部记录中保留原句与待核实事项。

## 3. 全文统一的图形规则

### 3.1 先保持语义正确，再追求美观

每条连接都要能说明：谁向谁传递什么，或谁约束谁。若只是分类归属，不画成运行时的数据流。若只是说明文字，不画成实际算法模块。

不为减少交叉而擅自删除反馈、安全分支和关键接口；不为视觉完整而虚构连接、传感器输入、执行保护或已完成状态。

正文、旧图和源码若存在差异，先记录差异。只有可靠材料支持时才修改，并记录依据；不能凭通用系统知识把用户的实际系统悄悄改成“应该有的系统”。

### 3.2 形状与颜色：少而准确

默认使用矩形/圆角矩形表示功能模块，浅色容器表示职责或部署边界，清楚标注的数据对象表示输出。

圆柱只在确实表达存储、日志或数据库时使用。不要把 UDP 协议、置信度标量、授权或任务动作都画成圆柱。

菱形用于明确的条件判定，并给出对应分支条件。行为树的控制节点和条件节点应采用一致、解释清楚的记号，不机械套用普通流程图。

每张图通常使用 3–4 类有意义的配色，必要时另设安全强调色。不要每个模块一种颜色；同一颜色在同一图中不能同时表示处理阶段和完成状态。

线型必须有定义。实线、虚线不能一会儿表示反馈、一会儿表示计划、一会儿又表示注释而不解释。尽量通过直接文字标注和图例消除歧义。

### 3.3 字体与最终尺寸

以编译进论文后的实际尺寸验收，而不是在 draw.io 中放大验收。

本项目建议目标：关键标签最终约 9–11 pt；次要说明一般不低于 8 pt。具体服从现有论文规范，不把这个建议当学校硬性规定。达不到时优先减字、增大图高、拆分或转表，不首先缩字。

节点通常保留一行名称和一行必要解释。确有必要超过两行时，增加空间或使用外部说明，不裁掉重要含义。

同一图内字体层级、边框、箭头与间距统一。图内短句不承担整段正文的功能。

### 3.4 版面与连线

主阅读方向保持稳定。反馈线可以逆向，但优先沿专用边缘通道，不穿过节点和正文标签。

节点之间留出专门的连线空间。箭头接到节点边界，不穿入文字。连接标签不要贴在交叉点；标签白底不能把箭头或其他关系遮没。

可以使用子图，优先同一 figure 下的 (a)/(b)；若拆分后仍缩得很小，应改成独立图并同步更新引用。不要为了少一个图号，把两张复杂图又塞回原来的小面积。

### 3.5 导出与复现

保留唯一权威绘图源及稳定导出方式。论文优先使用已经验证可编译的矢量 PDF；SVG 作为可选中间或交换格式，不强求当前 LaTeX 构建支持新的插件。

检查中文、数学符号、上下标、字体替换、裁剪边界和留白。不要仅通过提高 DPI 掩盖字号过小。

导出命令以本地安装版本的帮助和项目说明为准，不猜测 CLI 参数。确实缺少转换工具时记录阻塞，不覆盖原可用图。

AI 生图可用于少数困难图的布局参考，但本任务不以它为依赖。最终连接和文字必须由论文与源码确定；不得用生成图替代曲线、设备照片或真实界面截图。

## 6. 与章节重构联合执行的顺序

第一步：清查源文件，保存基线，确认新章节中每图的职责和去向。

第二步：先做代表样图：F03（部署）、F09（复杂数据流）、F11（行为树）。实际导出并编译，检验通用字号、线型与版式是否成立。

第三步：依据样图规范完成其余 P0，再完成 P1 和 P2。不要所有图同时随机换风格。

第四步：将新图接回最终章节，更新图题、引用及正文解释，检查拆图、合图后的论证顺序。

第五步：对所有本次修改图的最终论文页面逐页检查，不仅抽看独立 PNG。复杂图再放大检查文字碰撞；正常页面尺寸检查可读性。

如使用多代理并行，应按独立图或图族分工。主代理负责公共样式、主 tex、章节编号、图源清单和最终构建；多个代理不能同时修改同一主文件或共享生成脚本。

不要为了图像任务改动控制、安全、采集和仿真的业务逻辑。无法确认的技术关系单独记录，继续完成其他不受影响的图。

## 7. 每张图的验收表

请将下表逐图填写到 `thesis_refactor.md` 的图像章节，或沿用项目已有的等价记录。不要再建立大量重复 Markdown。

| 项目 | 必填内容/判据 |
|---|---|
| 定位 | 旧图号、当前 label、源文件、最终导出路径 |
| 章节归属 | 最终章节及首次解释位置；不写死旧页码 |
| 图的职责 | 用一句话说明只回答什么问题 |
| 语义核查 | 节点、方向、优先级、条件、层级与正文/实现一致 |
| 修改方式 | 保留/轻修/重排/拆分/合并；写实际做了什么 |
| 可编辑性 | 权威源真实可编辑，不是整图位图套壳 |
| 几何质量 | 非预期重叠、截字、穿字、遮挡为零；必要交叉可明确辨认 |
| 实际字号 | 按论文缩放后检查关键标签与说明，不按编辑器放大倍率检查 |
| 可追溯性 | 原数据和生成源不被改写；设计/仿真/实测性质明确 |
| 复现 | 使用已核验的生成/导出方式；不存在下次生成覆盖整改的问题 |
| 编译检查 | 引用、子图、字体和符号正确，无本次引入的丢图 |
| 页面检查 | 独立成图和论文实际页面均已打开检查 |
| 最终状态 | PASS / BLOCKED / NOT APPLICABLE，以及未通过的具体原因 |

自动检查可以辅助发现边界框碰撞、越界和重复 label，但不等于语义或视觉验收。容器包含子节点、连线与节点连接、标签遮线等情况必须按实际含义判断，不机械地把所有框相交都判错。

对于复杂图，连续两轮微调仍无法在目标尺寸下读清，应改用拆图、表格或不同视图，不继续缩字。此处是改变处理方式的触发点，不是允许未通过验收就结束。

BLOCKED 不计为完成。不能只在清单中承诺“已优化”，必须附真实新源文件、导出和最终页检查记录。
