## 必须实验 2：等效通电电缆磁场扫描实验

### 目的

证明你的海缆磁场模型和横向定位/埋深反演不是纯理论，而是能在等效通电导体上被实测验证。

### 依赖设备

- 可调直流稳压电源 60 V / 20 A；
- 大功率铝壳电阻；
- RVV 铜芯电源线；
- 鳄鱼夹、接线端子；
- 磁传感器；
- SK2301 ADC；
- Jetson；
- 卷尺/标尺；
- 非铁磁支架或简易滑轨。

### 大致怎么做

你可以先做最简单的一维横向扫描。

1. 用电源线布置一条直线“等效海缆”；
2. 用直流电源 + 大功率电阻形成稳定电流回路；
3. 设置多个电流档位，例如 1 A、2 A、5 A、10 A；
4. 将磁传感器固定在支架上；
5. 设定传感器到导线的高度，例如 5 cm、10 cm、20 cm、30 cm；
6. 沿横向位置扫描，例如 -50 cm 到 +50 cm，每 2–5 cm 一个点；
7. 每个点采集 5–10 秒磁数据；
8. 计算该点磁场均值和标准差；
9. 拟合 Biot-Savart 或简化导线磁场模型；
10. 反推出导线横向位置和等效深度/距离。

### 如果要模拟交流海缆

你可以用功放 + 低频信号源/音频输出做 45–50 Hz 交流激励，但要注意安全与电流能力。更稳妥的是：

- 先用直流实验验证空间衰减；
- 再用低压交流小电流验证频率提取；
- 不必一开始就追求大电流 50 Hz 三相。

声呐同学滞后是现实风险。你不能等他。你的策略应该是：

> **先把声呐从“真实设备”降级为“接口、数据结构、置信度通道和失效模式”。**

这样你仍然能证明系统架构支持声磁协同，只是当前实物阶段声呐由仿真/回放/占位器输入替代。

### 本仓库已有接口基础

该实验不是从零设计。仓库中已经有一条可复用的软件链路：

- `brain_linux/src/auv_bridge/auv_bridge/bridge_backends.py` 在 Zenoh JSON 与 protocol UDP 两个后端中都保留 `cable_sonar_observation_key`，可把仿真/占位声呐观测送入同一桥接节点。
- `brain_linux/src/auv_bridge/auv_bridge/bridge_node.py` 已发布 `/auv/sensors/cable_sonar_observation`，并把上游 keyexpr 解码为 ROS2 观测消息。
- `brain_linux/src/auv_control/auv_decision_ros/perception_quality_node.py` 订阅 `/auv/sensors/cable_sonar_observation`，输出 `/auv/perception/quality/sonar`，适合验证声呐质量分与置信度衰减。
- `brain_linux/src/auv_control/auv_decision_ros/tracking_authority_node.py` 消费感知质量话题，可验证声呐退化后 TRACK/HOLD/SEARCH 授权如何变化。
- `scripts/start_experiment.sh` 已支持 `--inject-missing-forward-sonar`、`--enable-mock-forward-sonar-wrapper`、`--mock-forward-sonar-*` 等参数，可在不接真实声呐的条件下注入缺失、延迟或低置信度场景。

### 最小实验定义

该实验的目标不是证明“真实声呐已经可用”，而是证明“声呐作为一个异步观测模态已经具备可替换接口、质量传播和降级闭环”。最小闭环为：

1. 启动 ROS2 brain stack、bridge、perception quality、tracking authority 和 cable tracking。
2. 磁通道使用真实采集、实测回放或固定磁场剖面；声呐通道使用仿真/回放/占位器，输出统一字段：时间戳、横向偏差、相对方位或局部中心线、置信度、可见性、噪声等级、失效标志。
3. 注入四类声呐退化：置信度下降、短时不可见、固定延迟、虚警。
4. 记录 `/auv/perception/quality/sonar`、`/auv/cable/confidence`、`/auv/cable/tracking`、`/auv/cable/mode`、`/auv/bt_status` 和 rosbag。
5. 输出三张图或表：声呐置信度时间线、EKF/电缆跟踪状态变化、行为树/授权状态切换。

### 通过判据

| 判据 | 解释 |
|---|---|
| 接口稳定 | 替代声呐源与真实声呐源使用相同字段和话题，节点无需改代码 |
| 置信度可传播 | 声呐质量下降时，`/auv/perception/quality/sonar` 和 `/auv/cable/confidence` 同步下降 |
| 融合可降级 | 声呐不可见或延迟时，估计器增大声呐协方差并保留磁/DVL/深度链路 |
| 行为可切换 | TRACK 不满足时进入 HOLD/SEARCH/退出等保守状态，而不是继续假装稳定跟踪 |
| 边界可说明 | 论文只声称接口、异步融合和失效降级通过，不声称真实声呐成像或完整声磁实物融合已完成 |

### 大致怎么做

1. 定义声呐观测接口：
   - 时间戳；
   - 目标横向偏差；
   - 置信度；
   - 是否可见；
   - 噪声等级；
   - 失效标志。

2. 使用三类声呐数据源：
   - 仿真生成；
   - 历史样例图像/人工标注数据；
   - 占位器程序按场景输出。

3. 与真实磁传感器数据并行进入 EKF：
   - 磁通道是真实采集；
   - 声呐通道是接口替代；
   - 测试异步融合和失效切换。

4. 注入声呐失效：
   - 声呐置信度降低；
   - 声呐短时不可见；
   - 声呐延迟；
   - 声呐虚警。

### 输出

- 声呐置信度变化下 EKF 状态估计变化；
- 声呐失效后磁通道接管；
- 声磁融合状态机/行为树切换；
- “接口已打通，但真实声呐待接入”的边界说明。

### 当前论文落点

- 方法章入口：`tab:ch03-sonar-substitution-contract` 已给出最小观测契约，当前论文可先声称“接口、异步接入、置信度传播与失效降级机制可验证”。
- 实验章入口：后续若实际运行该实验，结果应进入第 5 章实物证据容器，而不是混入三条仿真主线；结果形态优先为“故障注入表 + 置信度/状态切换时间线”。
- 结论章入口：若真实声呐仍未接入，第 6 章应写成“真实声呐成像精度待接入验证”，而不是削弱本文已完成的接口级声磁协同验证。

### 论文表述

> 受限于当前阶段声呐设备集成进度，本文在半实物实验中采用声呐观测接口替代真实声呐图像输入，重点验证声呐观测异步接入、置信度传播和失效降级机制。该实验不用于证明真实声呐成像性能，而用于验证声磁融合框架对声呐模态间歇可用性的兼容能力。

这个表述很安全。

### 当前已完成的前置部分（2026-08-21）

本轮已先完成“真实噪声进入磁观测链”的最小半实物版本，复现入口为：

```bash
real_experiments/mag_chain_noise/run.sh
```

该入口统一审计 `hardware_wrappers/fangkong_adc/raw_data/*.npz` 的 17 段三轴记录，并选取 `1780675809_291477.npz`、`1780676130_241387.npz` 两段无强 45 Hz 目标激励的记录作为默认背景噪声回放源。两段总时长 13.104 s；45 Hz 向量锁相幅值中位数为 2.584 nT，50 Hz 向量锁相幅值中位数为 169.284 nT，80--300 Hz 矢量幅度谱密度中位数为 0.133 nT/\(\sqrt{\mathrm{Hz}}\)。这说明当前宿舍环境记录主要携带真实工频背景，而 45 Hz 目标频率可以与 50 Hz 环境项分离。

进一步的半实物注入把上述背景噪声叠加到 \(I_{\mathrm{peak}}=2.6140\text{ A}\)、高度 0.20 m 的 45 Hz Biot--Savart 直导线目标上，再用同一锁相接口恢复幅值包络。两个背景段的幅值 RMSE 分别为 0.792 nT 和 0.271 nT，约为清洁目标峰值的 0.034\% 和 0.011\%。这可以写成“真实全链路背景噪声已能作为观测层回放输入进入仿真链”，但还不能写成“完整 AUV 实测闭环已完成”。

Linux 平台已完成首版 ROS2 父层接入：`real_experiments/mag_chain_noise_ros/run.sh` 将 `real_experiments/mag_chain_noise/data/noise_profile.json` 与两段原始背景记录接入 `decoupled_cable_sim_node.py` 的磁观测发布点，并在 Direction A 解耦电缆闭环中对比“清洁磁观测 / 协方差匹配高斯噪声 / 实测背景回放”三种输入。详细指标、图源和论文回填位置以 32 号交接文档为准；该结果仍只写作半实物观测回放，不写作完整 AUV 水下实测闭环。

`AUV-Master-Mag` 子仓验证已在 macOS 侧用 Python 3.14 临时环境复跑通过：`python -m unittest discover -s tests` 为 145 个用例全绿，`python main_demo.py --case case3 --no-viz` 可完成 200 s 高噪声无图仿真并进入 `track` 模式。需要注意，macOS 系统自带 Python 3.9 虽有部分科学计算依赖，但不支持子仓中的 PEP 604 类型标注；后续复现应使用 Python 3.10+ 并安装 `requirements.txt` 与测试用 `pytest`。

# 十一、对你当前局面的最重要建议

你现在不要再把主要风险理解为：

> “AUV 总装不了，所以实物实验做不了。”

应该改成：

> “完整 AUV 总装不了，但关键实物证据链仍然可以拆出来做，而且这些证据更直接支撑论文创新点。”

你真正必须守住的是以下五句话：

1. **我真实搭建了磁感知采集链。**
2. **我用等效通电电缆验证了磁场模型和定位反演。**
3. **我识别并测试了 AUV 载荷中的电磁干扰和屏蔽问题。**
4. **我把 EKF、UA-MPC、BT 部署到了 Jetson 并验证了实时性。**
5. **我用半实物通信实验验证了双脑架构的心跳、自救和降级机制。**

只要这五句话都有图、有表、有数据、有脚本，你的论文即使没有完整 AUV 下水，也能形成一个比较稳的答辩版本。

# 十二、最终建议：答辩叙事怎么收束

如果 AUV 不能总装，你的答辩叙事建议是：

> 本文面向存量 AUV 平台的海缆自主巡检改造任务，提出了声磁协同感知、不确定性驱动控制和双脑安全自治架构。受限于整机总装与声呐集成进度，本文没有将完整 AUV 水下巡检作为唯一验证路径，而是采用“仿真闭环 + 关键链路实物实验 + 双脑半实物验证”的分层验证策略。仿真部分验证算法闭环性能，实物部分验证磁感知链路、等效电缆磁场反演、电磁干扰抑制和 Jetson 实时部署，半实物部分验证双脑通信、心跳超时和安全降级。该验证体系能够支撑本文方法的可行性结论，同时完整水下自主巡检仍作为后续工程集成工作开展。

这套说法是安全的、诚实的，也比较符合工程型硕士论文的答辩逻辑。
