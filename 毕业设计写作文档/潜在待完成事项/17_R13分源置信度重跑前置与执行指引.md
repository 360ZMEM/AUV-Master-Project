# R13 分源置信度重跑前置与执行指引

## 1. 当前判定

旧 R13 已完成数值失败归因，但不能继续用于“在线不确定性适应”结论。其 UA 输入
来自定位协方差常量映射，约为 0.367；六个代理配置中的磁噪声、声呐噪声和电缆
几何没有进入该标量。

本轮没有运行 R13 正式矩阵。已完成的工作是把下一轮所需的测量、估计、权限、
控制和实验门控全部接到代码中，并用离线 preflight、权重扫描和单场景 pilot
验证。

## 2. 仿真中的替代关系

下一轮不得把 cable truth、到缆距离或场景编号直接映射为 confidence。允许的链路
只有：

```text
PVS cable geometry + scenario noise
  -> MagneticSampleBlock / SonarCableObservation
  -> perception_quality_node
  -> p_detect / estimate / covariance / p_track
  -> TrackingAuthorityMachine (TRACK/SEARCH/HOLD)
  -> ConservativeQualityControlPolicy
  -> speed limit + confidence + delta_u_penalty_scale
  -> MPC
```

其中磁源在缺少非 truth 的动态几何上下文时只提供 `p_detect`；R13 的 `p_track`
当前由声呐线点、稳健拟合残差和协方差产生。前视地形声呐仍只提供地形坡度，
不得替代 cable sonar。

## 3. 已完成前置

### 3.1 测量与桥接

- Mock AMD 以 5 Hz 发布 2 kHz、至少 0.18 s 的三轴 45 Hz 磁块；
- 同一场景生成 body-frame cable-sonar 线点、CNR、可见长度、歧义和截断；
- `protocol_udp` Zenoh 旁路订阅两个新 key，并转换成 ROS2 类型消息；
- 原单点磁场、UDP 遥测和 forward sonar 接口保持兼容；
- 六个 proxy YAML 均声明两个新 uplink key。

### 3.2 标定域

- R13 使用 `simulation_proxy` 专用曲线；
- 两份曲线均为 `physical_deployment_approved=false`；
- 默认实物节点只接受 `physical` 域；
- `target_signal_scale=0.002` 是代理动态范围参数，不是实物辨识结果。

### 3.3 P5/P6

- P5 authority 已实现 health、detection、tracking 三重独立门控；
- TRACK/SEARCH/HOLD 已有进入/退出迟滞和连续帧去抖；
- P5 当前强制 `shadow_only=true`；
- P6 默认 `enable=false` 且拒绝 shadow；
- 仿真可显式允许 `simulation_proxy` shadow 驱动控制；
- conservative MPC 在低 `p_track` 时降速、提高控制代价并增加
  \(\Delta U\) 惩罚；旧激进模式只保留作历史复现。

### 3.4 实验门

`run_proxy_cable_sweep.py` 对任何包含 UA 的矩阵强制要求：

1. `confidence_source=source_specific`；
2. 六场景 preflight 为 pass；
3. preflight 中各 proxy YAML 的 SHA256 与当前文件一致；
4. calibration domain 为 `simulation_proxy`；
5. `confidence_policy=conservative`；
6. 至少一个正的 `delta_psi_cmd/delta_z_cmd/delta_T_cmd`；
7. 缺任一条件时在初始化实验包和启动 PVS 前退出。

## 5. R13 下一步严格顺序

### Step 1：重建与定向测试

```bash
cd brain_linux
source /opt/ros/humble/setup.bash
colcon build --executor sequential \
  --packages-select auv_interfaces auv_bridge auv_controller auv_decision_ros
colcon test --packages-select auv_bridge auv_controller auv_decision_ros
```

只看这三个包的当前结果；全局 `test-result` 会同时列出
`auv_decision_core` 既有的 LOCKED/IDLE 测试失败，不能混为本轮回归。

### Step 2：生成正式 preflight

应在准备运行 R13 的同一天重新生成，避免配置哈希过期：

```bash
python3 tools/preflight_r13_quality.py \
  --output /tmp/r13_quality_preflight.json
```

报告必须 `passed=true`。若只剩单源、`p_track` 跨度低于 0.12、磁检测重新饱和，
或 proxy YAML 在报告后发生修改，停止后续步骤。

### Step 3：权重小矩阵，不进入 R13 主结果

先用 R14 状态快照或单场景短 pilot 扫描 \(\Delta U\) 三项权重。选择规则按优先级：

1. 无求解回退和 50 ms 周期阻塞；
2. 控制变化率低于旧 UA；
3. 不以显著横向 RMSE 恶化换取平滑；
4. 低 `p_track` 时速度和 \(\Delta U\) 惩罚确实单调变化。

旧 dry-run 使用的 `0.05/0.05/0.01` 仅验证参数传递，在正式扫描中未达到 1%
平滑收益门。`r13_conservative_weight_preflight/20260810T000414` 对六组权重执行
36 个 R14 快照×3 个 `p_track` 工作点和 180 步确定性 S 弯闭环。全部 648 次快照
求解和 1080 个闭环周期均无 fallback 或 50 ms 阻塞。冻结结果为：

```text
delta_psi_cmd = 50.0
delta_z_cmd   = 10.0
delta_T_cmd   = 2.0
```

相对无 \(\Delta U\) 参考，归一化控制变化率从 0.14545 降至 0.14219，下降
2.24%；横向 RMSE 从 0.04963 m 降至 0.04781 m。该组是达到至少 1% 平滑收益门
的最小已测试正则化，不称为全局最优。冻结入口为
`brain_linux/config/r13_conservative_mpc_overrides.json`。

### Step 4：单场景双模式 pilot

正式矩阵前只运行 S-curve、单 seed、baseline/UA 各一次。pilot 必须验证：

- ROS 包中两个质量 topic 均有有效消息；
- baseline 和 UA 的外生输入哈希一致；该哈希覆盖场景、bridge 配置、seed 和
  测量生成器代码，不要求闭环分叉后的传感器 payload 相同；
- UA 的 `quality_control_policy.accepted=true`；
- authority 至少出现一种可解释状态，且 `p_track` 非常量；
- controller debug 记录 confidence、policy、\(\Delta U\) 倍率和求解统计；
- baseline 保持 `enable_quality_control=false`。

pilot 未通过时，运行包保留为 invalid，不得进入六场景矩阵。

首轮 20 s pilot 因磁源合法的 `p_track=NaN` 被诊断 JSON 拒绝而失败，原包保留在
`20260809_235524_r13_v2_source_specific_pilot`。修复只把诊断层非有限值编码为
`null`，未改变 ROS 质量消息语义。最终 repair2 位于
`20260810_000151_r13_v2_source_specific_pilot_repair2`，机器审计 15 项全部通过：
两源各有 51/52 帧有效质量消息，sonar `p_track` 为 0.868--0.943，authority
出现 HOLD 和 TRACK，UA confidence 为 0.881--0.936，动态 \(\Delta U\) 倍率为
1.191--1.358；baseline 保持禁用，两个模式均无 fallback 和周期阻塞。

## 6. R13-v2 完成判据

每个运行至少保存：

- 原始磁块和 sonar observation；
- 两源 `PerceptionQuality`；
- `CableTrackingAuthority`；
- controller debug 与累计 solver 计数；
- 配置、seed、代码版本、preflight SHA256 和 calibration ID；
- 失败包及 invalid 原因。

聚合必须同时报告：

- `p_detect/p_track` 的 p5、p50、p95 和动态范围；
- TRACK/SEARCH/HOLD 占比及切换次数；
- 速度缩放、\(\Delta U\) 惩罚倍率；
- RMSE、控制变化率、安全违规、fallback、blocked 和 wall-time；
- baseline/UA 成对效应及 seed 离散。

若任一 UA 场景 `p_track` 的 p95-p5 小于 0.12，或 policy 未实际接管，该运行只能
作为基础设施证据。若 conservative UA 仍无正收益，应保留为有效负结果，不再回到
“低置信提高跟踪权重并降低控制代价”的旧映射。
