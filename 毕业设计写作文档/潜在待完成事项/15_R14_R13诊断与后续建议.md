# R14：R13 诊断与后续建议

## 1. 结论

R13 的首轮结果不能解释为“不确定性感知控制降低坡面和综合场景安全违规”。
首轮矩阵同时混入了三个独立问题：

1. 深度动力学采用不可导的硬俯仰饱和，导致长预测域求解器持续达到迭代上限；
2. `/auv/controller/debug` 是 0.5 s 低频快照，首轮 0.90--0.99 表示诊断快照
   处于回退状态的比例，不是严格逐周期概率；
3. UA 实际使用的置信度几乎恒为 0.367，场景和 seed 间变化小于 0.002，
   因而首轮比较是固定低置信权重与固定权重的比较，不是在线适应实验。

R14 已修复第 1 项并补齐第 2 项的诊断字段。第 3 项需要在 R22 前重构置信接口，
之后才能重跑具有在线适应意义的六场景主矩阵。

## 2. 求解失败根因

旧预测模型使用

\[
\theta=\operatorname{clip}(-k_z(z_{\rm cmd}-z),-\theta_{\max},\theta_{\max}).
\]

当前 \(k_z=0.8\)、\(\theta_{\max}=20^\circ\)。R13 首帧绝对深度误差为
0.595--2.326 m，全部进入或显著越过饱和区。最小复现实验表明：

- 速度误差 0.442 m/s 单独存在：N=20，4 次迭代成功；
- 航向误差约 1.7° 单独存在：N=20，5 次迭代成功；
- 深度误差 0.69 m 单独存在：N=20，100 次迭代失败；
- 单独关闭速率约束或带宽约束不能恢复收敛；
- 将预测域缩至 N=5 可以成功，但会牺牲预瞄长度。

修复采用

\[
\theta=\theta_{\max}\tanh
\left(\frac{-k_z(z_{\rm cmd}-z)}{\theta_{\max}}\right),
\]

保持物理边界不变，同时消除零梯度平台。

### 3.2 18 组关键场景闭环

发卡、坡面和综合极端各执行 baseline/UA×3 seed×30 s：

- 18/18 运行和控制聚合有效；
- baseline 平均求解 15.23 ms，UA 为 16.83 ms；
- fallback 均为 0；
- 末端约束违反量级降至 \(10^{-6}\)；

因此首轮 R13 的表观安全改善主要受 fallback 持有行为影响，修复后不再复现。

## 4. 置信度与权重机制诊断

UA 的置信度由水平位置协方差绝对迹映射：

\[
c=\exp[-(P_{xx}+P_{yy})/\sigma_{\rm ref}].
\]

R13 各包的 \(c\) 均约为 0.367。这一数值接近 \(\exp(-1)\)，表明当前映射主要
反映固定初始化尺度，而非代理场景中的声磁质量、地形或横流变化。在该置信度下：

- 横向与航向跟踪权重固定放大约 2.01 倍；
- 深度跟踪权重固定放大约 1.25 倍；
- 控制努力惩罚固定降至约 0.394 倍。

综合极端三种子机制分解：

| 变体 | 横向 RMSE | 控制变化率 | 安全违规率 | fallback |
|---|---:|---:|---:|---:|
| baseline | 4.4686 m | 42.07 | 0.2590 | 0 |
| 当前 UA | 4.4143 m | 86.73 | 0.3322 | 0 |
| 关闭控制降权 | 4.3392 m | 52.71 | 0.3020 | 0 |
| 关闭跟踪放大 | 3.9755 m | 80.92 | 0.2341 | 0 |

控制降权是控制变化率增大的主要来源；固定跟踪放大也未在该场景产生安全或精度
收益。由于置信度没有动态激励，这一结果只否定当前固定工作点，不否定重新标定后
的 UA 机制。

## 5. 基础设施问题

两次无有效观测包的失败来自 `colcon` 并行构建竞态：多个 Python 包同时重写
`install/*egg-info`，另一个 `setup.py` 读取到临时缺失的 `entry_points.txt`。
已将 `start_lin_brain.sh` 改为 `--executor sequential`。正式 sweep 仍建议：

1. 实验前单独完成一次构建和定向测试；
2. 正式矩阵使用 `AUV_SKIP_BRAIN_BUILD=1`；
3. 启动失败必须标为 invalid，不能仅凭主脚本退出码记为运行成功。

## 6. 针对 R13 的后续建议

### P0：保留当前修复

1. 保留平滑俯仰饱和和 N=20；当前快照 p95 已低于 50 ms，不应先牺牲预瞄长度；
2. N=5 仅作为算力不足时的降级档，不作为根因修复；
3. 保留每次运行复位的 solver attempt/success/fallback/blocked 累计计数，以终值相除计算逐周期率；
4. 正式运行采用预构建和顺序构建，消除空包竞态。

### P1：重构置信接口后再重跑 R13

把单一 confidence 拆成可审计的三个字段：

- `state_confidence`：按状态估计分源 NIS、协方差增量和观测新鲜度构造；
- `cable_confidence`：由声磁跟踪质量、可见性和残差构造；
- `control_confidence`：明确记录二者的组合规则及限幅。

新增完成门控：

- 每个 UA 场景的 confidence p95-p5 必须超过预设动态范围；
- baseline 与 UA 必须复用相同物理输入；
- 每周期记录实际 confidence、跟踪权重倍率和控制惩罚倍率；
- 若 confidence 未响应场景注入，该运行只能进入基础设施证据。

### P1：重新辨识权重映射

1. 在有动态置信输入后重新扫描跟踪放大上限和控制惩罚下限；
2. 增加 \(\Delta U\) 代价，特别约束推力变化；现有速率约束只覆盖航向和深度指令；
3. 不建议在缺少动态置信时继续微调 sigmoid 中点或斜率；
4. 以 RMSE、安全违规和控制变化率三目标 Pareto 前沿选择参数，不能只优化其中一项。

### P2：正式重跑

完成上述两项后，重新执行六场景×两模式×三 seed×60 s：

- 首轮 R13 保留为“数值失败与证据治理”负结果；
- 新矩阵必须逐周期统计，而不是使用 debug 快照比例；
- 同时报告 confidence 动态范围、权重倍率、求解耗时和失败样本；
- 只有新矩阵才能用于 UA 在线适应的最终优劣结论。
