## 2. R15 每周期诊断

### 2.1 语义修复

旧失败路径在优化器异常时把 `solve_time_ms` 写成 0，随后上层
`FALLBACK_LAST_OUTPUT` 又直接修改并返回上一成功 `ControlOutput`。因此旧包中的失败
帧可能同时携带“当前失败状态”和“上一成功耗时”，不能用于失败实时性归因。

当前实现把控制输出与求解诊断分离：

- 复用上一输出时只复用推力、制导航向和制导深度；
- 当前失败周期创建新的 debug 记录；
- 失败 wall time 从本周期 `perf_counter` 取得；
- 求解异常携带结构化 diagnostics，而不是只依赖异常字符串；
- 成功、最大迭代失败和其他异常使用同一字段集合。

### 2.2 每周期字段

| 类别 | 字段 |
|---|---|
| 求解状态 | `solver_return_status`、`solver_iterations`、`solver_success` |
| 实时性 | `solver_wall_time_current_ms`、`control_period_ms`、`control_period_blocked` |
| warm-start | `warm_start_provided`、`warm_start_used`、`warm_start_control_shift_rms` |
| 初值连续性 | `state_initial_jump_l2` |
| 可行性 | `initial/final_constraint_violation_max/l2`、`initial/final_active_constraint_count` |
| 回退 | `fallback_type`、`fallback_reason`、`last_successful_solver_status` |

活跃约束按距上下界不超过 \(10^{-4}\) 判定。失败周期可从 CasADi 最新迭代点读取
最终约束残差；若求解器在产生迭代点前异常，则字段保留为不可观测，不伪造零值。

### 2.3 发布、聚合与 bundle

`/auv/controller/debug` 已透传上述字段。`tools/aggregate_control_metrics.py` 将每包
聚合为有效 debug 样本数、失败事件数、能力门控状态、当前周期 wall time 最大值、
fallback 类型集合，以及迭代数、周期阻塞率和约束残差统计。

`tools/run_thesis_sweep.py` 与 `tools/run_proxy_cable_sweep.py` 在
`finalize_bundle()` 前自动读取 MCAP 并回填 R04 五个诊断字段。dry-run 没有 bag 时
仍保持 `contract_complete=false`；正式运行只有实际读到 debug 样本后才闭合契约。

## 3. R12 归一化覆盖扫描

### 3.1 模型

声呐理想横向带宽与联合有效宽度定义为

\[
W_{\mathrm{s}}=2h\tan(\beta/2),\qquad
W_{\mathrm{eff}}=\min(W_{\mathrm{s}},W_{\mathrm{m}}).
\]

令 \(\lambda=d/W_{\mathrm{eff}}\)，横向误差界
\(e=\epsilon W_{\mathrm{eff}}\)，则

\[
C_{\mathrm{g}}
=\min\left(1,\frac{\max(1-2\epsilon,0)}{\lambda}\right).
\]

矩形区域的航线数、含半圆换向的航程与任务时间分别为

\[
n=\left\lceil\frac{B-W_{\mathrm{eff}}}{d}\right\rceil+1,\quad
S=nL+(n-1)\pi d/2,\quad T=S/v.
\]

### 3.2 扫描矩阵与结果

扫描轴为 4 档波束角、4 档磁有效宽度比、5 档间距比、4 档速度比和 4 档横向
误差比，共 1280 个解析组合，全部进入 R04 bundle 且校验通过。

参考工况 \(\epsilon=0.10\) 的结果为：

| 间距比 | 重叠率 | 保证覆盖率 | 航线数 | 归一化航程 | 时间指数 |

| 0.6 | 40% | 100.0% | 33 | 1350.16 | 1.311 |
| 0.7 | 30% | 100.0% | 29 | 1190.79 | 1.156 |

## 4. R09 Jetson handoff

Jetson 上的单命令入口为：

```bash
bash scripts/run_jetson_clean_benchmark.sh
```

默认矩阵：

| 阶段 | 工况 | 默认规模 |
|---|---|---:|
| 系统短测 | baseline、combined，UA-MPC | 120 s/场景 |
| MPC 稳态档 | start=target=3 m，cold/warm | 200 次/模式 |
| MPC 约束压力档 | start=8 m、target=3 m，cold/warm | 50 次/模式 |
| 热稳定 | combined，UA-MPC | 1800 s |

runner 强制检查 Jetson release、`tegrastats`、25 W NVPModel、至少 8 个在线核和浏览器
背景负载；每阶段同步保存命令日志、`tegrastats` 原始日志与解析 CSV、进程 CPU/内存
采样、bag、配置快照和 R04 bundle。`--recover PATH` 可把历史 Jetson bag 或
microbench 目录纳入返回包，但历史产物仍须依靠其自身元数据，不能用当前 commit
冒充生成版本。

本机 dry-run 明确检测到缺少 Jetson release、`tegrastats` 和 25 W NVPModel，
因此只生成 handoff，不产生任何真机性能数值，且
`status.json.contract_complete=false`。
