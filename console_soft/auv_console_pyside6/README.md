## 1. 概述

本上位机控制台是基于 PySide6 开发的 AUV 地面控制站，支持以下核心功能：

- **手动遥控模式 (MANUAL)**：通过摇杆直接控制 AUV 推力和舵角
- **自主授权模式 (AUTONOMY)**：向 Jetson 仲裁器下发语义任务指令，由 AUV 自主执行
- **紧急切断 (ESTOP)**：立即停止所有推力并锁死系统状态
- **离线回放**：基于 PCAP 文件的协议回放，用于调试和分析

### 1.1 架构升级说明 (v2.0)

本版本实现了 **上位机 → Jetson → AMD 三端链路架构**，核心变化包括：

| 特性 | v1.0 | v2.0 |
|------|------|------|
| 通信模式 | PC 直连 AMD | PC → Jetson (Zenoh) → AMD |
| 手动控制 | UDP 直发 72 字节 CKTH | UDP 直发 + Zenoh JSON 双通道 |
| 自主控制 | 无 | 语义 JSON 任务指令 |
| 急停逻辑 | 简单推力归零 | 显式锁死 + 推力归零检查 |
| 链路监控 | 无 | 分层超时 + 置信度显示 |

## 3. 快速开始

### 3.1 环境要求

- **Python 版本**: >= 3.10
- **依赖库**:
  ```bash
  pip install PySide6 pyzenoh3 numpy pyyaml
  ```

### 3.2 配置文件

配置文件位于 `console_soft/auv_console_pyside6/console_config.yaml`：

```yaml
zenoh:
  router_ip: "127.0.0.1"    # Zenoh Router IP 地址
  router_port: 7447         # Zenoh Router 端口
  mode: "client"            # 连接模式：client

udp:
  amd_ip: "192.168.0.101"   # AMD PC104 的 IP 地址
  amd_port: 52364           # AMD 监听端口
  local_port: 52365         # 上位机本地端口

communication:
  heartbeat_hz: 5.0         # 心跳频率 (5Hz = 200ms)
  pc_timeout_s: 1.5         # 上位机失联超时 (秒)
  soft_warning_s: 1.0       # 软警告阈值 (秒)

defaults:
  work_mode: 1              # 1=SEND_ONLY, 2=SEND_RETURN
  target_depth_m: 5.0       # 默认目标深度 (米)
  track_distance_m: 500.0   # 默认跟踪距离 (米)
  task_timeout_s: 1200      # 默认任务超时 (秒)
  mission_type: "CABLE_TRACKING"  # 默认任务类型
```

### 3.3 启动步骤

1. **确保 Zenoh Router 已启动**（如需要 Zenoh 通信）：
   ```bash
   zenohd --listen tcp/127.0.0.1:7447
   ```

2. **启动上位机**：
   ```bash
   cd console_soft/auv_console_pyside6
   python3 src/main.py
   ```

3. **连接 AUV**：
   - 点击菜单栏 `连接` → `启动 UDP 通信`
   - 确认底部状态栏显示 "UDP 通信已启动"

4. **选择工作模式**：
   - 默认进入 **手动遥控模式 (MANUAL)**
   - 需要自主任务时，点击底部 `手动遥控 MANUAL` 按钮切换至 **自主模式 (AUTONOMY)**

## 5. 底部控制台操作区

底部控制台是 **最高优先级操作区**，所有关键控制按钮均在此区域。

### 5.1 紧急切断区 (ESTOP)

```
┌──────────────────┐
│ 🛑 紧急切断 ESTOP │  ← 红色按钮，点击后立即触发急停
│ 🔓 解除急停       │  ← 橙色按钮，仅在推力归零时可点击
└──────────────────┘
```

#### 触发急停

- **点击** `🛑 紧急切断 ESTOP` 按钮
- 系统立即执行：
  1. 所有推力归零 (`motor_speed1 = 0`, `motor_speed2 = 0`)
  2. 工作指令设为 `0x02` (TASK_CANCEL)
  3. 控制模式强制为 `0x01` (MANUAL)
  4. 状态锁死 (`estop_locked = True`)
  5. 模式切换按钮禁用
  6. 通过 UDP 和 Zenoh 双通道发送 ESTOP 包

#### 解除急停

- **条件**：
  1. 推力必须归零 (`motor_speed1 < 0.1` 且 `motor_speed2 < 0.1`)
  2. 点击 `🔓 解除急停` 按钮
- **结果**：
  1. 急停状态解除 (`estop_active = False`, `estop_locked = False`)
  2. 模式切换按钮恢复
  3. 仲裁状态恢复为 `REMOTE`
  4. 系统恢复手动遥控模式

> **⚠ 重要提示**：急停是**显式锁死**机制，必须手动解除，不会自动恢复！

### 5.2 模式切换区

```
┌──────────────────────┐
│ 手动遥控 MANUAL      │  ← 点击切换至自主模式
│ 自主授权 AUTONOMY    │  ← 点击切换回手动模式
└──────────────────────┘
```

- **手动遥控 (MANUAL)**：
  - 默认模式
  - 摇杆输入直接控制 AUV
  - 发送 72 字节 CKTH 包 (UDP 直发 AMD)
  - Jetson 仲裁器执行 **透明路由**，原样转发

- **自主授权 (AUTONOMY)**：
  - 点击按钮切换至此模式
  - 上位机发送语义 JSON 任务指令 (Zenoh)
  - Jetson 仲裁器执行 **MPC 自动驾驶**
  - 推力输入被忽略 (固定为 0)

### 5.3 任务参数配置区

```
┌──────────────────────────────────────────────────────────────┐
│ 任务类型: [CABLE_TRACKING ▼]                                │
│ 目标深度: [5.0] 米    跟踪距离: [500.0] 米                   │
│ 超时时间: [1200] 秒   [📤 下发任务指令]                      │
└──────────────────────────────────────────────────────────────┘
```

| 参数 | 说明 | 默认值 | 范围 |
|------|------|--------|------|
| 任务类型 | 自主任务类型 | CABLE_TRACKING | CABLE_TRACKING / ZIGZAG_SEARCH |
| 目标深度 | 下潜深度 (米) | 5.0 | 0.5 ~ 100.0 |
| 跟踪距离 | 任务执行距离 (米) | 500.0 | 10.0 ~ 10000.0 |
| 超时时间 | 任务超时 (秒) | 1200 | 60 ~ 3600 |

#### 下发任务指令

- **前提条件**：必须处于 **自主模式 (AUTONOMY)**
- **操作**：点击 `📤 下发任务指令` 按钮
- **执行**：
  1. 构建 JSON 任务指令：
     ```json
     {
       "control_mode_byte": 238,
       "work_instruction": 1,
       "mission": "CABLE_TRACKING",
       "search_depth": 5.0,
       "track_distance": 500.0,
       "timeout_s": 1200,
       "thrust": 0.0,
       "mode": "AUTONOMY"
     }
     ```
  2. 通过 Zenoh 发布到 `rt/pc/cmd_raw` 话题
  3. Jetson 接收到后解析并发布到 `/auv/mission_command`
  4. AUV 行为树接收任务并开始执行

### 5.4 Zenoh 连接区

```
┌──────────────────────┐
│ 🟢 Zenoh: 已连接      │  ← 绿色表示已连接，红色表示未连接

```

- **连接**：点击按钮，连接到 Zenoh Router (默认 `tcp/127.0.0.1:7447`)
- **断开**：点击按钮，断开 Zenoh 连接
- **状态指示**：
  - 🟢 绿色：已连接
  - 🔴 红色：未连接/连接失败

> **提示**：Zenoh 连接仅在自主模式下需要，手动模式不依赖 Zenoh。

### 5.5 任务状态显示区

```
┌──────────────────────────────────────────┐

│ 剩余时间: 660 秒                         │

```

- 显示当前任务的执行进度
- 实时更新剩余时间和任务状态

## 6. 三种工作模式

### 6.1 手动遥控模式 (MANUAL)

**适用场景**：
- 调试 AUV 基础功能
- 短距离精细操控
- 紧急情况下的手动接管

**操作方式**：
1. 确认底部按钮显示 `手动遥控 MANUAL`（未按下）
2. 使用摇杆控制推力和舵角
3. 系统每 600ms 发送一次 CKTH 包

**数据包格式**：
- 协议：UDP 直发
- 格式：72 字节 CKTH 包
- 目标：AMD PC104 (`192.168.0.101:52364`)
- 控制模式字节：`0x01`

**Jetson 行为**：
- 仲裁器处于 `REMOTE` 模式
- 执行 **透明路由**，将 PC 包原样转发
- 不修改任何控制参数

### 6.2 自主授权模式 (AUTONOMY)

**适用场景**：
- 电缆跟踪任务
- 之字形搜索任务
- 长时间自主作业

**操作方式**：
1. 点击底部按钮切换至 `自主授权 AUTONOMY`
2. 配置任务参数（目标深度、跟踪距离等）
3. 点击 `📤 下发任务指令`
4. 系统每 200ms 发送一次自主心跳包

**数据包格式**：
- 协议：Zenoh JSON
- 话题：`rt/pc/cmd_raw`
- 控制模式字节：`0xEE` (PID 自动驾驶)

**Jetson 行为**：
- 仲裁器切换至 `AUTONOMOUS` 模式
- 执行 **条件拦截**，将任务指令转换为 MPC 控制输出
- 发布遥测数据至 `rt/auv/telemetry`

### 6.3 紧急切断模式 (ESTOP)

**适用场景**：
- AUV 行为异常
- 传感器数据异常
- 通信链路中断
- 任何需要立即停止的情况

**操作方式**：
1. 点击 `🛑 紧急切断 ESTOP` 按钮
2. 系统立即停止所有推力
3. 状态锁死，无法自动恢复
4. 确认安全后，点击 `🔓 解除急停`

**数据包格式**：
- 协议：UDP + Zenoh 双通道
- 控制模式字节：`0x01` (手动模式)
- 工作指令：`0x02` (TASK_CANCEL)
- 推力：`0, 0`

## 7. 通信配置

### 7.1 修改 Zenoh Router IP

编辑 `console_config.yaml`：

```yaml
zenoh:
  router_ip: "192.168.1.100"  # 修改为 Jetson 的实际 IP
  router_port: 7447
```

### 7.2 修改 AMD IP

```yaml
udp:
  amd_ip: "10.0.0.50"   # 修改为 AMD 的实际 IP
  amd_port: 52364
  local_port: 52365
```

### 7.3 调整心跳频率

```yaml
communication:
  heartbeat_hz: 10.0    # 提高至 10Hz (100ms)
  pc_timeout_s: 1.0     # 缩短超时时间
  soft_warning_s: 0.8   # 缩短软警告阈值
```

> **注意**：心跳频率越高，网络负载越大，但响应更及时。海上 WiFi 环境建议使用 5Hz。

## 8. 仲裁与链路状态监控

### 8.1 仲裁状态

| 状态 | 颜色 | 说明 |
|------|------|------|
| `REMOTE` | 🟢 绿色 | 上位机拥有控制权 |
| `AUTONOMOUS` | 🔵 蓝色 | Jetson 拥有控制权 |
| `ESTOP LOCKED` | 🔴 红色 | 紧急切断锁死 |
| `请求自主...` | 🟡 黄色 | 正在等待 Jetson 确认 |

### 8.2 置信度显示

置信度反映链路质量，范围 0.0 ~ 1.0：

| 范围 | 颜色 | 说明 |
|------|------|------|
| >= 0.7 | 🟢 绿色 | 链路质量良好 |
| 0.5 ~ 0.7 | 🟡 黄色 | 链路质量一般，注意监控 |
| < 0.5 | 🔴 红色 | 链路质量差，可能触发自主模式拒绝 |

### 8.3 链路时延

显示遥测数据从 AUV 到上位机的传输延迟（毫秒）：

- **< 100ms**：正常
- **100ms ~ 500ms**：可接受
- **> 500ms**：延迟较高，可能影响控制响应

### 8.4 拒绝原因

当 Jetson 拒绝自主模式请求时，显示拒绝原因：

| 原因 | 说明 | 处理建议 |
|------|------|----------|
| `NONE` | 无拒绝 | 正常 |
| `LEAK` | 检测到漏水 | 立即检查舱室密封 |
| `LOW_BATTERY` | 电池电压过低 | 更换电池或充电 |
| `LOW_CONFIDENCE` | 置信度过低 | 检查传感器状态 |
| `MANUAL_OVERRIDE` | 上位机手动覆盖 | 确认是否需要手动接管 |

## 9. 离线回放模式

### 9.1 功能说明

离线回放模式允许加载 PCAP 文件，重放历史通信数据，用于：
- 调试协议解析逻辑
- 分析历史任务数据
- 验证仲裁器行为

### 9.2 使用方法

1. 点击菜单栏 `工具` → `切换到离线模式`
2. 选择 PCAP 文件（默认 `PC104.pcapng`）
3. 系统自动加载并开始回放
4. 遥测数据会实时更新显示

### 9.3 回放配置

编辑模式配置文件（通常位于 `config/mode_config.yaml`）：

```yaml
offline:
  pcap_file: "PC104.pcapng"
  replay_interval_ms: 600
  loop_playback: true
```

## 10. 安全注意事项

### 10.1 急停机制

- **急停是最高优先级操作**，会立即中断所有其他操作
- 急停后**必须手动解除**，系统不会自动恢复
- 解除急停前**必须确认推力归零**
- 急停状态下**无法切换模式**

### 10.2 链路超时保护

Jetson 仲裁器实施了分层超时机制：

| 超时类型 | 阈值 | 触发动作 |
|----------|------|----------|
| 软警告 (Soft Warning) | 1.0s 未收到 PC 数据 | 记录警告，监控链路 |
| 硬超时 (Hard ESTOP) | 1.5s 未收到 PC 数据 | 强制 ESTOP，锁死系统 |

> **重要**：如果上位机程序崩溃或网络中断超过 1.5 秒，Jetson 会自动触发急停！

### 10.3 通信通道冗余

- **手动模式**：UDP 直发 AMD（不依赖 Zenoh）
- **自主模式**：Zenoh JSON（需要 Zenoh Router）
- **急停模式**：UDP + Zenoh 双通道（最大可靠性）

### 10.4 推力归零检查

解除急停时，系统会检查推力是否归零：

```python
thrust_ok = (abs(motor_speed1) < 0.1 and abs(motor_speed2) < 0.1)
if not thrust_ok:
    # 拒绝解除急停
    print("⚠ 推力未归零，无法解除急停")
```

**如果推力未归零**：
1. 将摇杆回中
2. 等待推力显示归零
3. 再次点击 `🔓 解除急停`

### 10.5 自主模式前置检查

切换到自主模式前，Jetson 会检查：
- [ ] 无漏水报警
- [ ] 电池电压正常
- [ ] 传感器置信度 >= 阈值
- [ ] 通信链路正常

如果任何检查失败，自主模式将被拒绝。

## 11. 常见问题排查

### 11.1 Zenoh 连接失败

**症状**：点击连接后状态显示红色

**排查步骤**：
1. 确认 Zenoh Router 已启动：
   ```bash
   ps aux | grep zenohd
   ```
2. 确认 Router IP 和端口配置正确：
   ```bash
   cat console_config.yaml | grep router_ip
   ```
3. 测试网络连接：
   ```bash
   ping <router_ip>
   ```
4. 检查防火墙规则：
   ```bash
   sudo iptables -L | grep 7447
   ```

### 11.2 UDP 通信失败

**症状**：遥测数据不更新

**排查步骤**：
1. 确认 AMD IP 和端口配置正确
2. 使用 `tcpdump` 抓包检查：
   ```bash
   sudo tcpdump -i any port 52364 -v
   ```
3. 检查网络连接：
   ```bash
   ping <amd_ip>
   ```

### 11.3 急停无法解除

**症状**：点击 `🔓 解除急停` 无响应

**排查步骤**：
1. 检查推力显示是否归零
2. 如果推力不为零，将摇杆回中
3. 等待推力显示 `< 0.1`
4. 再次点击解除按钮

### 11.4 自主模式被拒绝

**症状**：切换至自主模式后，仲裁状态显示拒绝原因

**排查步骤**：
1. 查看 `拒绝原因` 标签
2. 根据原因采取对应措施：
   - `LEAK`：检查舱室密封
   - `LOW_BATTERY`：更换电池
   - `LOW_CONFIDENCE`：检查传感器连接
   - `MANUAL_OVERRIDE`：确认是否需要手动接管

### 11.5 任务指令未响应

**症状**：点击 `📤 下发任务指令` 后 AUV 无响应

**排查步骤**：
1. 确认已处于自主模式
2. 确认 Zenoh 连接正常（绿色）
3. 查看消息日志，确认任务指令已发送
4. 检查 Jetson 日志：
   ```bash
   journalctl -u auv_bridge -f
   ```

### 11.6 遥测数据延迟高

**症状**：链路时延显示 > 500ms

**排查步骤**：
1. 检查网络带宽占用
2. 降低心跳频率（修改 `heartbeat_hz`）
3. 检查 WiFi 信号强度
4. 考虑切换到有线连接调试
