# Foxglove 布局生成器调试上下文（2026-03-25）

## 1. 这次问题是什么

Foxglove Desktop 打开布局时报错：

- `c.split is not a function`

这个错误出现在使用参数化布局生成器之后，说明问题不在运行时话题链路本身，而更可能在**布局 JSON 结构**或**布局 schema 兼容性**上。

---

## 2. 已确认的根因方向

这次排查中，已经确认以下几点：

1. 参考实现是可用的
   - `Console上位机软件/ros2_ws/foxglove_layout.json`
   - 该文件能作为 Foxglove Desktop 导入参考

2. 旧版参数化生成器容易引入歧义
   - `configById + layout` 的写法是正确方向
   - 但 Foxglove Desktop 导入时，布局叶子必须使用 `PanelType!slug`，不能直接写 `Speed`、`Depth` 这种裸名字

3. `tabs` / 自定义容器并不是第一优先
   - 为了降低 schema 风险，当前生成器改成只使用 `row` / `column` 的 split 树
   - 避免让 Foxglove 在解析层猜测复杂容器

---

## 3. 这次采用的修复策略

### 3.1 结构对齐

生成器现在输出的布局结构，尽量对齐参考文件中的 Desktop 布局风格：

- 顶层 `configById`
- 顶层 `globalVariables`
- 顶层 `userNodes`
- 顶层 `playbackConfig`
- 顶层 `layout`

### 3.2 面板对齐

当前默认面板包括：

- `3D!auv3d`
- `Plot!depth`
- `Plot!speed`
- `Plot!control`
- `RawMessages!imu`
- `RawMessages!dvl`
- `RawMessages!state`
- `RawMessages!setpoint`
- `RawMessages!cmdvel`
- `RawMessages!status`

### 3.3 布局叶子对齐

布局树的叶子只引用面板 key，例如：

- `3D!auv3d`
- `Plot!depth`
- `Plot!speed`
- `Plot!control`
- `RawMessages!imu`

不要再把布局叶子写成 `tabs` 节点、裸名字，或其它未验证容器。

---

## 4. 调试注意点

### 4.1 如果再次出现 `c.split is not a function`

按下面顺序检查：

1. 是否导入了正确的 JSON 文件
   - 只导入 `auv_layout.generated.json`
   - 不导入 `.meta.json`

2. 顶层结构是否是 Desktop 可识别的导出样式
   - `configById`
   - `layout`
   - `globalVariables`
   - `userNodes`

3. 布局叶子是否只引用面板 key
   - 叶子必须是 `PanelType!slug`
   - 叶子不能是任意字符串容器
   - 叶子不能是未定义的面板名

4. `configById` 是否与 `layout` 一致
   - `layout` 里用 `Plot!speed`
   - `configById` 里也必须存在 `Plot!speed`

5. 3D 配置是否过于“定制化”
   - 先去掉地图层，只保留 Grid
   - 确认基础 3D 能导入后，再逐步增加层

### 4.2 哪些字段最容易踩坑

- `followMode`
- `topics`
- `paths`
- `layout` 的 split 树
- `panelType` / `type` 是否与 Desktop 预期一致
- `configById` key 是否写成了裸名字

### 4.3 最稳妥的排查姿势

1. 先生成最小布局
2. 先只保留 3D + 1 个 Plot + 1 个 Raw
3. 导入成功后再逐步加面板
4. 最后再恢复完整布局

---

## 5. 这次的新实现约束

- Foxglove 布局生成器只负责输出 JSON，不直接参与 ROS2 运行
- topic 定义继续单独放在 `foxglove_layout_project/config/topics.py`
- 新增 Zenoh 发布项前，必须先确认布局里有对应消费面板
- 如果要扩展 UI，优先改 generator，不要在脚本里硬编码布局内容
- 任何新面板节点都必须先定义成 `PanelType!slug`，再写入 `configById` 和 `layout`

## 8. 后续如果再出问题怎么处理

如果后续 Foxglove 仍然无法导入，下一步不要先改脚本，而是：

1. 把生成 JSON 与参考 JSON 做逐字段 diff
2. 优先删减 3D 的复杂配置
3. 优先删减布局里的嵌套层级
4. 确认 `layout` 只由 `row` / `column` split 组成
5. 确认 `panels` 的 `id` / `type` / `config` 完整

这个文档就是后续 Foxglove 调试的上下文入口。
