## 5. 运行验证（话题级）
### 5.1 话题存在性
执行命令：

```bash
source /opt/ros/humble/setup.bash

```

观测到关键话题：
- `/auv/control/goal`
- `/auv/control/setpoint`
- `/auv/sensors/depth`
- `/auv/sensors/dvl`
- `/auv/sensors/imu`
- `/auv/sensors/status`
- `/auv/state/covariance`
- `/auv/state/filtered`
- `/cmd_vel`

### 5.2 控制链路回显
执行命令：

```bash
timeout 5s ros2 topic echo /auv/control/setpoint --once
timeout 5s ros2 topic echo /cmd_vel --once
```

观测结果：
- `/auv/control/setpoint` 收到目标：
  - `mode: ZIGZAG_SEARCH`
  - `target_depth_m: 4.0`
  - `target_speed_mps: 0.4`
- `/cmd_vel` 收到控制输出：
  - `linear.x`、`angular.x/y/z` 有数值输出

结论：
- 决策输出到控制输出链路已形成闭环（在 ROS2 侧内部可见）。

### 5.3 传感输入可用性
执行命令：

```bash
timeout 5s ros2 topic echo /auv/sensors/imu --once
timeout 5s ros2 topic echo /auv/sensors/dvl --once
timeout 5s ros2 topic echo /auv/sensors/depth --once
```

观测结果：
- 5 秒内未收到消息。
- 与 bridge 日志 `waiting for sensor payloads...` 一致。

结论：
- 当前问题不在 ROS2 栈内部，而在上游仿真数据尚未注入（HoloOcean/Zenoh 发布侧未联上或未发包）。
