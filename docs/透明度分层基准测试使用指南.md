# 透明度分层基准测试使用指南

## 快速开始

### 前置条件

1. **ROS2 环境**：确保已安装 ROS2 Humble 并正确配置
2. **编译完成**：brain_linux 工作空间已编译（`colcon build`）
3. **依赖工具**：安装了 mcap 和分析工具依赖

```bash
# 安装Python依赖
pip install mcap mcap-ros2-support matplotlib numpy
```

### 基本使用

```bash
# 进入项目目录
cd /home/gwxie/master_work-tmp/AUV_Master_Project

# 运行基准测试（使用默认参数）
./scripts/run_transparency_level_benchmark.sh

# 查看结果
cat log/transparency_benchmarks/$(ls -t log/transparency_benchmarks | head -1)/report.md
```

## 详细参数说明

### 命令行选项

```bash
./scripts/run_transparency_level_benchmark.sh [选项]
```

| 选项 | 说明 | 默认值 |
|------|------|--------|
| `--warmup SECONDS` | 预热时间（秒），等待系统启动 | 6 |
| `--duration SECONDS` | 录制时长（秒） | 20 |
| `--output-root PATH` | 输出目录 | `log/transparency_benchmarks` |
| `--bag-arg ARG` | 额外的rosbag记录参数（可重复） | - |
| `-h, --help` | 显示帮助信息 | - |

### 示例用法

```bash
# 快速验证测试（最短时间）
./scripts/run_transparency_level_benchmark.sh --warmup 4 --duration 10

# 标准性能测试
./scripts/run_transparency_level_benchmark.sh --warmup 6 --duration 30

# 长期稳定性测试
./scripts/run_transparency_level_benchmark.sh --warmup 10 --duration 60

# 自定义输出目录
./scripts/run_transparency_level_benchmark.sh --output-root /tmp/my_benchmarks

# 添加rosbag参数（例如：指定缓存大小）
./scripts/run_transparency_level_benchmark.sh --bag-arg --max-cache-size 104857600
```

## 等待机制说明

### 为什么需要等待机制？

基准测试需要录制 `/auv/state/filtered` 话题的数据，该话题由 `auv_localization_node` 发布。由于节点启动和数据流依赖，需要以下条件满足后才能开始录制：

1. **仿真环境启动**：HoloOcean 仿真初始化
2. **传感器桥接就绪**：传感器数据开始发布
3. **定位节点启动**：`auv_localization_node` 完成初始化
4. **ES-EKF 初始化**：滤波器收到第一组传感器数据
5. **状态估计发布**：`/auv/state/filtered` 开始发布消息

### 等待机制工作流程

```
1. 启动AUV栈（仿真 + ROS2）
   ↓
2. 等待预热时间 (默认6秒)
   ↓
3. 开始验证循环（最多30秒）
   ↓
4a. 检查 /auv/state/filtered 话题是否存在
   ↓
4b. 检查是否有发布者
   ↓
4c. 等待2秒确保第一条消息
   ↓
5. 开始录制rosbag
   ↓
6. 录制指定时长
   ↓
7. 停止录制和栈
   ↓
8. 分析rosbag数据
```

### 超时处理

如果在30秒内 `/auv/state/filtered` 未开始发布：

```
[AUV][WARN] timeout waiting for /auv/state/filtered after 30s
[AUV][WARN] proceeding with recording anyway, but diagnostics may be incomplete
```

脚本会继续执行，但分析结果可能不完整。如果频繁出现超时，请检查：

1. 系统资源是否充足
2. 仿真是否正常启动
3. 网络连接是否正常（如果使用远程机器）
4. 增加预热时间：`--warmup 10`

## 故障排查

### 常见问题

#### 1. 所有指标都是 `nan`

**原因**：`/auv/state/filtered` 未被录制到

**解决方案**：
```bash
# 检查分析日志
cat log/transparency_benchmarks/<run_id>/level_1/analyze.log

# 如果显示 "Missing estimated-state samples"
# 检查启动日志
cat log/transparency_benchmarks/<run_id>/level_1/launch.log | grep -i error

# 检查rosbag中录制的主题
ros2 bag info log/transparency_benchmarks/<run_id>/level_1/rosbag
```

#### 2. 等待超时

**原因**：系统启动时间超过预期

**解决方案**：
```bash
# 增加预热时间
./scripts/run_transparency_level_benchmark.sh --warmup 10 --duration 20
```

#### 3. 录制时长不足

**原因**：录制时间太短，样本不够

**解决方案**：
```bash
# 增加录制时长
./scripts/run_transparency_level_benchmark.sh --duration 30
```

#### 4. 分析工具失败

**原因**：缺少Python依赖或rosbag损坏

**解决方案**：
```bash
# 重新安装依赖
pip install --upgrade mcap mcap-ros2-support matplotlib numpy

# 验证rosbag文件
mcap info log/transparency_benchmarks/<run_id>/level_1/rosbag/*.mcap

# 手动运行分析
python3 tools/analyze_bag.py log/transparency_benchmarks/<run_id>/level_1/rosbag
```

## 性能调优

### 预热时间选择

根据机器性能选择合适的预热时间：

| 机器类型 | CPU | 内存 | 推荐预热时间 |
|----------|-----|------|--------------|
| 高性能工作站 | 8+ 核心 | 16GB+ | 4-6 秒 |
| 普通笔记本 | 4 核心 | 8GB | 8-12 秒 |
| 虚拟机 | 2-4 核心 | 4-8GB | 12-20 秒 |
| 低配置机器 | 2 核心 | 4GB | 20+ 秒 |

### 录制时长选择

根据测试目的选择录制时长：

| 测试类型 | 录制时长 | 样本数（约） | 适用场景 |
|----------|----------|--------------|----------|
| 快速验证 | 10 秒 | 200-300 | 功能测试、CI/CD |
| 性能基准 | 20-30 秒 | 400-600 | 性能对比、回归测试 |
| 稳定性测试 | 60 秒 | 1200-1800 | 长期行为观察 |
| 压力测试 | 120 秒+ | 2400+ | 极限情况、边界测试 |

## 高级用法

### 批量测试

创建批量测试脚本：

```bash
#!/bin/bash
# batch_benchmark.sh

WARMUP_VALUES=(4 6 8)
DURATION_VALUES=(10 20 30)

for warmup in "${WARMUP_VALUES[@]}"; do
  for duration in "${DURATION_VALUES[@]}"; do
    echo "Running: warmup=$warmup, duration=$duration"
    ./scripts/run_transparency_level_benchmark.sh \
      --warmup "$warmup" \
      --duration "$duration" \
      --output-root "log/batch/w${warmup}_d${duration}"
  done
done
```

### 结果对比

使用Python脚本对比多次运行结果：

```python
# compare_benchmarks.py
import pandas as pd
from pathlib import Path

# 读取多次运行的摘要
results = []
for run_dir in Path('log/transparency_benchmarks').iterdir():
    if run_dir.is_dir():
        summary_file = run_dir / 'summary.csv'
        if summary_file.exists():
            df = pd.read_csv(summary_file)
            df['run_id'] = run_dir.name
            results.append(df)

# 合并并显示
combined = pd.concat(results, ignore_index=True)
print(combined.groupby('level_name').agg({
    'speed_target_mean_mps': ['mean', 'std', 'min', 'max']
}))
```

### 集成到CI/CD

在GitHub Actions或其他CI系统中运行基准测试：

```yaml
# .github/workflows/benchmark.yml
name: Benchmark Tests

on: [push, pull_request]

jobs:
  benchmark:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - name: Setup ROS2
        run: |
          source /opt/ros/humble/setup.bash
          colcon build --packages-select auv_*
      - name: Run Benchmark
        run: |
          source install/setup.bash
          ./scripts/run_transparency_level_benchmark.sh \
            --warmup 4 --duration 10
      - name: Upload Results
        uses: actions/upload-artifact@v2
        with:
          name: benchmark-results
          path: log/transparency_benchmarks/
```
