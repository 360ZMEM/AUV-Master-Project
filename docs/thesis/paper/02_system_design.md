# 第 2 章：系统设计与建模

## 2.1 任务需求分析与行业标准对齐

### 2.1.1 探测精度约束

海缆巡检对探测精度提出了明确要求。行业标准如《DL/T 1278-2025 海底电力电缆运行规程》中对磁探测灵敏度和埋深误差有具体规定。本项目以 0.05 nT 级磁传感灵敏度和 0.2 m 级埋深反演误差为设计目标，这些数值来源于标准条款或传感器手册，正式论文中需补充原文引用。

| 指标 | 设计目标 | 来源 | 当前验证状态 |
|---|---|---|---|
| 磁传感灵敏度 | 0.05 nT | DL/T 1278-2025 / 传感器手册 | TODO: cite 确认来源 |
| 埋深反演误差 | 0.2 m | 行业要求 | 待硬件实验验证 |
| 近底安全距离 | 3–5 m | AUV 作业约束 | 已在 terrain benchmark 中验证 |

### 2.1.2 作业环境约束

AUV 近底作业面临多类环境约束：近底流场（剪切流、横流、流向突变）、地形起伏（坡面、沟槽、悬跨）、声呐可见性变化（浑浊、底质变化、局部掩埋）和磁场背景噪声（三相抵消、铠装屏蔽、外部电磁干扰）。这些约束共同决定了系统设计的复杂度——单一传感器或单一控制器无法覆盖所有工况。

### 2.1.3 系统安全约束

任何自主控制指令都必须能够被上位机授权、监控和急停。感知异常或优化器求解失败不应直接穿透到执行层。本文通过行为树 failsafe 节点、安全仲裁器、上位机 ESTOP 双通道和 VxWorks 失联保护机制共同构成安全约束体系。

## 2.2 AUV 多源异构双脑硬件架构设计

### 2.2.1 架构选型逻辑

本文系统采用"执行层 + 感知决策层"的异步双脑架构。执行层由 AMD/VxWorks（实物部署阶段）或等价实时控制端承担，负责底层舵机驱动、推进器控制、遥测采集和失联保护；感知决策层由 Jetson/ROS2 承担，负责状态估计、行为树任务调度、路径生成和控制参考计算。

这种分工避免了两类常见陷阱：一是把高复杂度感知算法（EKF、MPC、行为树）直接塞入实时执行板，导致算力不足和实时性崩溃；二是让非实时 Linux 进程直接承担最后安全边界，导致异常状态下无法保证执行器安全响应。

代码库中通过 `Generic_AUV_Interface` 抽象层实现环境切换：仿真时使用 `Mock_AMD_Interface`，真机时使用 `PC104_UDP_Interface`。切换环境只需修改 yaml 配置中的 `protocol_udp.remote_host`，不修改主线控制代码。

### 2.2.2 五层软件架构

系统在软件层面自顶向下分为五层，每层职责单一，通过明确接口与相邻层交互：

| 层级 | 路径 | 职责 |
|---|---|---|
| 应用层 | `apps/` | 入口脚本，初始化配置、组装依赖、启动主循环 |
| 接口层 | `interfaces/` | 对外部系统（仿真器、通信中间件、硬件）的适配封装 |
| 行为层 | `behavior/` | 安全守卫、状态机、命令过滤等运行时行为管理 |
| 算法层 | `algorithm/` | 核心控制/导航/估计算法的纯计算实现 |
| 协议层 | `common/` | 数据结构定义、枚举、物理常量、环境工具等公共基础设施 |

这种分层架构使仿真验证和实物部署共享同一套算法层和行为层代码，仅替换接口层实现。

### 2.2.3 仿真后端与实物层对比

| 维度 | PVS 仿真 | HoloOcean 仿真 | Mock AMD | VxWorks 实物 |
|---|---|---|---|---|
| 物理保真度 | 中（Fossen 模型） | 高（流体、碰撞） | 通信延迟/丢包模拟 | 真实声学通道 |
| 适用阶段 | 算法开发/CI | 系统集成/视觉验证 | 仿真期通信模拟 | 实物部署 |
| 运行环境 | 纯 CPU | 需 GPU/显示 | 纯 Python | AMD 嵌入式板 |
| 对应层级 | 仿真后端 | 高保真后端 | 仿真通信层 | 执行层 |

### 2.3.2 三相交流电缆的螺旋漏磁模型

三相交流电缆的磁场建模比单芯复杂得多。三相电流的相位差导致磁场在空间上部分抵消，铠装层的屏蔽效应进一步衰减外部磁场，导线的螺旋绞合使漏磁特征呈现周期性变化。这些效应共同导致：有效信号更弱、空间分布更复杂、对传感器位置和方向更敏感。

| 效应 | 物理机制 | 对探测的影响 |
|---|---|---|
| 相位抵消 | 三相电流相位差 120° | 总磁场幅值降低，特征方向变化 |
| 铠装屏蔽 | 金属铠装层的涡流屏蔽 | 外部磁场进一步衰减 |
| 螺旋绞合 | 导线螺旋排列 | 漏磁呈现周期性空间变化 |

## 2.5 通信拓扑与电气隔离

### 2.5.1 UDP 二进制协议设计

PC/Jetson 与 AMD/VxWorks 之间的通信采用二进制 UDP 协议。下行帧 `$CKTH` 长度 72 字节，携带工作模式、任务指令、舵角、推力和可调参数；上行帧 `$AUV` 长度 145 字节，携带姿态、GPS、DVL、深度、电池、温度、漏水和故障位图。

| 帧方向 | 帧标识 | 长度 | 主要载荷 |
|---|---|---|---|
| 下行 | `$CKTH` | 72 B | 控制模式、工作指令、舵角、推力、12 个可调浮点参数 |
| 上行 | `$AUV` | 145 B | roll/pitch/yaw、GPS、DVL 三轴速度、深度、电压、温度、漏水、故障位图 |

UDP 协议的优点是轻量、易于与 VxWorks 对齐、延迟可控；缺点是需要严格处理字节序（小端序）、帧头、缩放因子、校验和和版本偏差。Python 端与 VxWorks 端独立开发过程中已发现 7 处已知偏差，包括帧头长度差异、压力与航向字段错位、深度缩放因子不一致、舵角类型符号约定不同等。这些偏差在仿真期已通过协议单元测试闭环，实物部署时需逐一复核。

### 2.5.2 电气隔离与 ±15V 隔离电源

磁传感器对电磁干扰极为敏感。系统采用 ±15V 隔离电源为磁传感器独立供电，避免与推进器和舵机的电源线共用，减少传导干扰。在仿真阶段，该隔离通过 `perception_engine.py` 中的磁饱和阈值和噪声注入模型间接体现；实物阶段需实际测量隔离效果。

### 2.5.3 上位机授权与安全闭环

上位机（PySide6 GUI）在系统中不是单纯显示界面，而是授权和安全控制节点。系统定义三种工作模式：

| 模式 | 通信方式 | 用途 |
|---|---|---|
| MANUAL | UDP `$CKTH` 包 | 直接操控舵角/推力，人工接管和现场调试 |
| AUTONOMY | Zenoh JSON | 下发任务目标给 Jetson，由 Brain 自主执行 |
| ESTOP | UDP + Zenoh 双通道 | 紧急停止一切自主动作，双通道确保至少一条路径可达 |

ESTOP 模式通过周期发送 `Work_Cmd=0x02 + Motor_Speed=0 + ctrl_mode=0x01` 的急停帧（20 Hz）实现。该急停链路独立于 ROS2/Zenoh，仅依赖 `common.protocol`，确保即使上层软件崩溃仍能发送停止指令。VxWorks 失联安全机制是冗余保险——当 Jetson 进程失联超过 1 s，AMD 自发停机。
