## 3. 已验证内容
以下内容已通过静态检查或语法检查：
- 新增 Python 文件无诊断错误
- 新增 shell 脚本语法正确
- brain_linux 中 ROS2 package 可被发现
- 等价性检查脚本 dry-run 路径解析正常

本轮新增运行态验证：
- `start_lin_brain.sh stack` 在系统 Python（`/usr/bin/python3`）下可稳定完成构建并拉起 4 个核心节点
- `ros2 topic list` 可见关键链路话题：`/auv/control/setpoint`、`/cmd_vel`、`/auv/state/filtered`、`/auv/sensors/*`
- `ros2 topic echo --once` 可观测到 `/auv/control/setpoint` 与 `/cmd_vel` 实际消息
- 传感输入话题在仿真桥接启动后可观测到实时消息，bridge 日志可给出 sensor ingress latency
- localization/controller/decision 均有持续运行日志，说明闭环已贯通

## 4. 当前仓库的实际能力
现在仓库已经具备以下能力：
1. 仿真侧可独立启动
2. 仿真侧可独立发布 Zenoh 数据
3. Linux 决策端可独立 build/启动 ROS2 包
4. common 契约已成为双端共享依据
5. 启动脚本已经覆盖 Linux/Windows 两侧
6. Linux 侧 bridge/localization/controller/decision 已可在统一 stack 下同时启动并持续运行
7. 决策到控制输出链路（`/auv/control/setpoint -> /cmd_vel`）已在 ROS2 内部可观测
8. 仿真桥接到 ROS2 传感输入链路已可观测到真实消息

但还不具备完整能力：
1. 仍需更长时间的稳定性回归与异常恢复测试
2. 端到端时延分布、丢包恢复和不同工况的行为树切换还未形成正式验收报告
3. 自动化回归脚本仍需进一步收敛为标准验收流程

推荐按这个顺序继续：
1. 定义 `auv_bridge` 接口桩和消息流向
2. 把仿真侧与 Linux 决策侧真正接起来

## 6. 风险点
当前最需要盯住的风险有：
- 协议字段漂移：仿真侧与决策侧字段名不一致
- 坐标系错误：UE4 / NED 转换混乱
- 脚本兼容问题：Linux 与 Windows 入口参数不一致
- 目录重名或错位：新旧包路径混淆
- 桥接缺失：看起来跑通，实际上没有真正闭环
