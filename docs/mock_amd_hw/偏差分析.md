# Python ↔ VxWorks 字节偏差分析

> 逐字段对比 `common/protocol.py` 的 `build_uplink_packet()` / `parse_uplink_packet()` 与 VxWorks `DataProcess.c` 的 `Pack_Data_To_UI12()`。

---

## 1. 差异总表

| # | 偏差点 | VxWorks | Python (`protocol.py`) | 严重程度 | 根因 |
|---|--------|---------|----------------------|----------|------|
| D1 | 帧头长度 | `$AUV` 4 字节 | `$AUV\x91` 5 字节 | 🟡 中 | Python 额外 1 字节 0x91（可能是协议子版本标记） |
| D2 | 字节 35-36 语义 | Pressure (PSI×1000) | orientation_deg (度×10) | 🔴 高 | 完全不同的字段占用同一偏移 |
| D3 | 深度缩放 | Depth×1 (u16) | depth_m×10 (u16) | 🟡 中 | 解码值差 10 倍 |
| D4 | 舵角类型/缩放 | u16 无符号 ×1 (已转度) | i16 有符号 ×10 | 🟡 中 | VxWorks 已在内部做 encoder→度转换 |
| D5 | 电机类型 | u16 无符号 | i16 有符号 | 🟢 低 | 负值 RPM 在物理上不可能 |
| D6 | 异常信息区 126-141 | 4×u32 完整位图 | 仅字节 127-129 (3×u8) | 🟡 中 | Python 丢失 Sys/Dev/BMS/Detail 位图 |
| D7 | 单体电压/温度 108-113 | 完整上报 | 硬编码 0 | 🟢 低 | Mock AMD 行为，非协议错误 |

---

## 2. 逐项详细分析

### D1: 帧头长度差异

**VxWorks**:
```c
u8 ToUI12_Head_Buf[4] = {"$AUV"};
memcpy(To_UI12_Buf, temp->ToUI12_Head_Buf, 4);
To_UI12_Buf[4] = temp->ToUI12_Msg_Length;  // 字节4=145
```

**Python**:
```python
PROTOCOL_UPLINK_HEADER = bytes((0x24, 0x41, 0x55, 0x56, 0x91))  # "$AUV\x91"
packet[0:5] = PROTOCOL_UPLINK_HEADER
# 字节 5 = frame_counter（VxWorks 中是字节 5 = Msg_Num）
```

**影响**: Python 将 `0x91` 作为协议版本标记放在帧头第 5 字节，VxWorks 在此位置放的是 `Msg_Length`。  
**结论**: 保持 Python 实现，标注 `KNOWN_DEVIATION_HEADER`。实物对接时需确认 VxWorks 侧是否也期望 `0x91`。

### D2: 字节 35-36 压力 vs 航向（最关键偏差）

**VxWorks**:
```c
temp->ToUI12_Pres = (Current_State.Current_Pres) * 1000;
To_UI12_Buf[35] = convert_u16_data1 >> 8;
To_UI12_Buf[36] = convert_u16_data1;
// 字节 35-36 = 内部压力（PSI × 1000）
```

**Python** (`build_uplink_packet`, protocol.py 行 823-824):
```python
struct.pack_into(">H", packet, 35, _clamp_int(round(orientation_deg * 10.0), 0, 65535))
# 字节 35-36 = 设定航向（度 × 10）
```

**Python** (`parse_uplink_packet`, protocol.py 行 857):
```python
internal_pressure_psi = struct.unpack(">h", packet[35:37])[0] * 0.001
# 解析时当作压力（PSI × 0.001），但构建时当作航向 — 构建与解析语义矛盾！
```

**影响**: 
1. Mock AMD 发出的字节 35-36 是航向，但 `parse_uplink_packet` 将其读为压力
2. VxWorks 发出的字节 35-36 是压力，Python 解析逻辑与 VxWorks 兼容但与 Python 构建逻辑矛盾

**结论**: 
- **不修改 protocol.py**（基线保护原则）
- 在测试中标注 `KNOWN_DEVIATION_BYTE_35_36`
- 实物对接前必须创建字段映射表，确认字节 35-36 的真实语义

### D3: 深度缩放差异

**VxWorks**:
```c
temp->ToUI12_Depth = Current_State.Current_Depth;  // ×1
// 字节 38-39: u16 BE, 原始深度值
```

**Python**:
```python
struct.pack_into(">H", packet, 38, _clamp_int(round(depth_m * 10.0), 0, 65535))
# 字节 38-39: u16 BE, 深度 × 10
```

**影响**: 同一个深度值 8.5m，VxWorks 编码为 8 (或 85 如果传感器分辨率是 0.1m)，Python 编码为 85。  
**结论**: 保持 Python ×10 精度，标注 `KNOWN_DEVIATION_DEPTH_SCALE`。

### D4: 舵角类型和缩放

**VxWorks 上行帧**:
```c
// 在 Pack_Data_To_UI12 中直接赋值已转换的度数
temp->ToUI12_HL_Rud_Angle = (LH_Ref_Location - Current_LH_Rud_Location) * 360 / 4096;
// 字节 27-28: u16 BE, 值范围 ~±180 度，无×10缩放
```

**VxWorks 下行解包**:
```c
// DataProcess.c 行 2462-2463
UI_WIFI_Instruction.FromUI12_RCD_LH_Set_Rud_Angle = (temp_buf[27]<<8) + temp_buf[28];
UI_WIFI_Instruction.FromUI12_RCD_LH_Set_Rud_Angle = UI_WIFI_Instruction.FromUI12_RCD_LH_Set_Rud_Angle / 10;
// 下行帧: 舵角字节是 ×10，解包时 ÷10 得到度数
```

**Python**:
```python
# 上行帧构建（mock_amd_server 不直接构建上行舵角，由 build_uplink_packet 处理）:
struct.pack_into(">h", packet, 27, _clamp_int(round(left_fin_deg * 10.0), -32768, 32767))
# i16 有符号 ×10
```

**总结**:
- 下行帧 $CKTH：VxWorks 和 Python 均为 **i16 ×10**，**一致** ✅
- 上行帧 $AUV：VxWorks 为 **u16 ×1**（已转度），Python 为 **i16 ×10**，**不一致** ⚠️

**结论**: 保持 Python 实现，标注 `KNOWN_DEVIATION_RUDDER_SIGN_SCALE`。

### D5: 电机 RPM 有/无符号

**VxWorks**: `u16` (无符号) — 物理上 RPM 不会为负  
**Python**: `i16` (有符号) — 允许反转指令  
**影响**: 正常范围内无影响。  
**结论**: 保持 Python 实现，标注 `KNOWN_DEVIATION_MOTOR_SIGN`。

### D6: 异常信息区差异

**VxWorks**:
```c
// 字节 126-141: 4 个 u32 位图
To_UI12_Buf[126-129]: Sys_Abnorm_Inf
To_UI12_Buf[130-133]: Dev_Abnorm_Inf
To_UI12_Buf[134-137]: BMS_Abnorm_Inf
To_UI12_Buf[138-141]: Dev_Abnorm_Inf_Detail
```

**Python**:
```python
# protocol.py 只使用了 3 个 u8 字节:
packet[127] = system_alarm & 0xFF
packet[128] = depth_alarm & 0xFF
packet[129] = bottom_alarm & 0xFF
# 字节 126, 130-141 未写入（保持 0）
```

**影响**: Python 上行帧的异常上报粒度远低于 VxWorks。  
**结论**: 保持现状，Mock AMD 场景下异常信息非关键。标注 `KNOWN_DEVIATION_ALARM_BYTES`。

---

## 3. 偏差决策汇总

| 标记名 | 偏差 | 是否修改 | 理由 |
|--------|------|----------|------|
| `KNOWN_DEVIATION_HEADER` | 帧头 4B vs 5B | 否 | 基线保护，实物前确认 |
| `KNOWN_DEVIATION_BYTE_35_36` | 压力 vs 航向 | 否 | 需实物确认语义，不在仿真层修改 |
| `KNOWN_DEVIATION_DEPTH_SCALE` | 深度 ×1 vs ×10 | 否 | Python 精度更高 |
| `KNOWN_DEVIATION_RUDDER_SIGN_SCALE` | 舵角 u16×1 vs i16×10 | 否 | 下行帧一致即可，上行 Mock 不影响控制 |
| `KNOWN_DEVIATION_MOTOR_SIGN` | 电机 u16 vs i16 | 否 | 正常范围无影响 |
| `KNOWN_DEVIATION_ALARM_BYTES` | 异常 4×u32 vs 3×u8 | 否 | Mock 场景下非关键 |

**原则**: 所有偏差在测试中以 `@pytest.mark.known_deviation("标记名")` 标注，不阻塞实施，但在实物对接前必须创建确认清单。
