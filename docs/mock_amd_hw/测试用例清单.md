## Phase 1: 协议合同测试

> 验证 Python codec 与 VxWorks `DataProcess.c` / `send_ckth_demo.py` 的字节级一致性。

### T1.1 下行帧 ($CKTH) 端序

- **目标文件**: `tests/test_protocol_contract.py`
- **测试函数**: `test_downlink_endianness`
- **输入**: 标准值 heading=180.0, depth=10.0, speed=1.5, 所有开关
- **断言**: `build_downlink_packet()` 输出的 72 字节帧中每个字段的字节序与 VxWorks `PackDataToCKTH` 一致
- **关键字段**: bytes 12-13 (heading×10, LE i16), bytes 14-15 (depth×10, LE i16), bytes 16-17 (speed×10, LE u16)
- **参考**: `docs/mock_amd_hw/协议合同映射.md` $CKTH 字节表

### T1.2 下行帧 ($CKTH) 缩放因子

- **测试函数**: `test_downlink_scaling`
- **用例表**:

| 参数 | 工程值 | 编码值 | 缩放因子 |
|------|--------|--------|----------|
| heading | 90.0° | 900 | ×10 |
| heading | 359.9° | 3599 | ×10 |
| depth | 0.0m | 0 | ×10 |
| depth | 50.0m | 500 | ×10 |
| speed | 0.0kn | 0 | ×10 |
| speed | 2.5kn | 25 | ×10 |

- **断言**: 每个编码值在帧中正确位置的 raw bytes 与期望一致

### T1.3 下行帧 ($CKTH) 校验和

- **测试函数**: `test_downlink_checksum`
- **输入**: 多组不同参数的下行帧
- **断言**: `byte 69 = sum(bytes[0:69]) & 0xFF`
- **边界**: 验证进位截断正确（sum=256+K → K）

### T1.4 上行帧 ($AUV) 端序

- **测试函数**: `test_uplink_endianness`
- **输入**: 构造完整的 `UplinkData` 数据类，调用 `build_uplink_packet()`
- **断言**: 每个 u16/i16/u32 字段在 145 字节帧中的字节序与 VxWorks `Pack_Data_To_UI12` 一致
- **关键字段**: bytes 6-7 (heading×10, LE i16), bytes 12-13 (DVL_speed×10, LE i16), bytes 28-31 (lon×1e6, LE i32), bytes 32-35 (lat×1e6, LE i32)

### T1.5 上行帧 ($AUV) 缩放因子

- **测试函数**: `test_uplink_scaling`
- **用例表**:

| 字段 | 工程值 | 编码值 | 缩放因子 | 偏移 |
|------|--------|--------|----------|------|
| heading | 180.5° | 1805 | ×10 | byte 6-7 |
| pitch | -5.3° | -53 | ×10 | byte 8-9 |
| roll | 12.7° | 127 | ×10 | byte 10-11 |
| dvl_speed | 1.23kn | 12 | ×10 | byte 12-13 |
| height | 2.5m | 25 | ×10 | byte 18-19 |
| voltage | 48.5V | 485 | ×10 | byte 20-21 |
| pressure | 5.123bar | 5123 | ×1000 | byte 35-37 |
| lon | 121.4734° | 121473400 | ×1e6 | byte 28-31 |
| lat | 31.2304° | 31230400 | ×1e6 | byte 32-35 |

### T1.6 上行帧 ($AUV) 校验和

- **测试函数**: `test_uplink_checksum`
- **断言**: `byte 142 = sum(bytes[0:142]) & 0xFF`

### T1.7 下行帧往返一致性

- **测试函数**: `test_downlink_roundtrip`
- **步骤**:
  1. `build_downlink_packet(已知参数)` → raw_bytes
  2. `parse_downlink_packet(raw_bytes)` → parsed
  3. 断言 `parsed.heading ≈ 原始值 ±0.1`（量化误差）
- **注意**: VxWorks 使用 i16 有符号，航向 359.9° → 3599 → 解析为 359.9

### T1.8 上行帧往返一致性

- **测试函数**: `test_uplink_roundtrip`
- **步骤**:
  1. 构造 `UplinkData(已知值)`
  2. `build_uplink_packet(data)` → raw_bytes
  3. `parse_uplink_packet(raw_bytes)` → parsed_data
  4. 断言各字段 `≈ 原始值 ±量化误差`
- **已知偏差**: bytes 35-37 (pressure vs orientation) 为 `KNOWN_DEVIATION_D1`，需特殊处理

### T1.9 上行帧异常位图

- **测试函数**: `test_uplink_anomaly_bitmap`
- **输入**: 设置各种异常标志位
- **断言**: Python 异常标志编码覆盖 VxWorks 4×u32 位图的核心子集
- **已知偏差**: `KNOWN_DEVIATION_D7` — Python 仅 3×u8，需注释说明

## Phase 2: 硬件行为测试

> 验证控制逻辑对极值、符号反转、死区等硬件特征的鲁棒性。

### T2.1 舵角极性测试

- **目标文件**: `tests/test_hw_behavior.py`（新增）
- **测试函数**: `test_rudder_polarity`
- **场景**: 发送 heading_dz = +10°（右转），验证下行帧中 rudder 字段方向正确
- **断言**: `parse_downlink_packet()` 中舵角原始值符号与期望一致
- **已知偏差**: `KNOWN_DEVIATION_D3` — Python i16×10 vs VxWorks u16°

### T2.2 舵角配平/零位测试

- **测试函数**: `test_rudder_trim_zero`
- **场景**: heading_dz = 0 → 舵角应为零位（通常 1500 或 0，取决于协议约定）
- **断言**: 帧中舵角字节为期望零位值

### T2.3 舵角死区测试

- **测试函数**: `test_rudder_deadzone`
- **场景**: heading_dz = 0.5°（小于典型死区 1°）
- **断言**: 帧中舵角未变化（仍在零位）

### T2.4 RPM 映射测试

- **测试函数**: `test_rpm_mapping`
- **场景**: speed_dz 从 0.0 到 3.0，步进 0.5
- **断言**: 帧中推进器 RPM 字段与速度期望值匹配
- **参考**: VxWorks 中的 speed→RPM 查找表（如果有）

### T2.5 心跳超时 — 仲裁器

- **目标文件**: `tests/test_arbiter.py`（扩展）
- **测试函数**: `test_heartbeat_timeout_fallback`
- **场景**: 模拟 MPC 指令超时（>0.5s 无新指令）
- **断言**: `CommandArbiter` 返回 `SAFETY_FALLBACK` 动作
- **依赖**: Mock 时间推进

### T2.6 心跳超时 — 自治守卫

- **目标文件**: `tests/test_autonomy_guard.py`（扩展）
- **测试函数**: `test_uplink_age_timeout`
- **场景**: 模拟上行帧 age > 200ms
- **断言**: `AutonomyGuard.permit()` 返回 False 或触发安全模式
- **依赖**: Mock 时间推进

### T2.7 电压下降 — 自治守卫

- **测试函数**: `test_voltage_low_guard`
- **场景**: 上行帧电压值 = 46.0V（低于 47V 阈值）
- **断言**: `AutonomyGuard.permit()` 返回 False

### T2.8 置信度不足 — 自治守卫

- **测试函数**: `test_confidence_low_guard`
- **场景**: 导航置信度 = 0.3（低于 0.5 阈值）
- **断言**: `AutonomyGuard.permit()` 返回 False

### T2.9 混沌注入 — DVL 冻结效果

- **目标文件**: `tests/test_mock_amd_chaos.py`（新增）
- **测试函数**: `test_chaos_dvl_freeze`
- **场景**: 配置 `dvl_freeze_enabled=true, dvl_freeze_after_s=1.0`，运行 2 秒
- **断言**: t=1s 后的上行帧中 DVL 速度值不再变化

### T2.10 混沌注入 — 上行棕色断电

- **测试函数**: `test_chaos_uplink_dropout`
- **场景**: 配置 `uplink_dropout_enabled=true, uplink_dropout_period_s=1.0, on_pct=0.5`
- **断言**: 在 2 秒内，上行帧发送数量约为期望的一半（±30%容差）
