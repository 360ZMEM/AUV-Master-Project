# 攻击站设计

> 独立脚本 `scripts/attacker_station.py`，模拟双主竞争场景下第二台控制台对同一 Mock AMD 的注入流量。

---

## 1. 设计目标

- 独立于 Mock AMD 服务器运行
- 向 Mock AMD 发送 $CKTH 指令帧，模拟另一台上位机的竞争流量
- 记录从发送到收到 $AUV 响应的往返时间（RTT）
- 可选导出 MCAP 格式供 Foxglove 回放

## 2. 脚本位置与接口

```
AUV_Master_Project/
  scripts/
    attacker_station.py    ← 新增
```

### 命令行接口

```bash
python scripts/attacker_station.py \
  --mock-amd-host 127.0.0.1 \
  --mock-amd-port 52364 \
  --listen-port 52367 \       # 本地接收 $AUV 的端口
  --profile conflict          # 预设: conflict / sweep / heartbeat
```

## 3. 预设模式

### 3.1 `conflict` — 双主竞争

模拟第二台上位机发送控制指令：

```python
def conflict_profile():
    """周期性发送随机 $CKTH 指令，与正常控制台流量竞争。"""
    while running:
        # 随机选择一种控制模式
        mode = random.choice([
            Mode.AUTONOMOUS.value,
            Mode.REMOTE.value,
        ])
        # 随机目标值
        heading = random.uniform(0, 360)
        depth = random.uniform(0, 50)
        speed = random.uniform(0, 2.0)

        packet = build_downlink_packet(
            mode=mode,
            heading_dz=heading,
            depth_dz=depth,
            speed_dz=speed,
            ...
        )
        sock.sendto(packet, (mock_amd_host, mock_amd_port))
        rtt = await_response(sock, listen_port, timeout=2.0)
        log_rtt(packet, rtt)
        time.sleep(0.5)  # 2Hz 竞争流量
```

### 3.2 `sweep` — 参数扫描

连续发送边界值指令，测试协议鲁棒性：

```python
def sweep_profile():
    """遍历关键参数的边界值，验证解析器不崩溃。"""
    test_cases = [
        # (heading, depth, speed, description)
        (0.0, 0.0, 0.0, "全零"),
        (359.9, 99.9, 3.0, "上界"),
        (360.0, 100.0, 3.1, "超上界"),
        (-1.0, -1.0, -0.1, "负值"),
        (180.0, 50.0, 1.5, "正常值"),
    ]
    for heading, depth, speed, desc in test_cases:
        packet = build_downlink_packet(
            heading_dz=heading, depth_dz=depth, speed_dz=speed, ...
        )
        sock.sendto(packet, (mock_amd_host, mock_amd_port))
        rtt = await_response(sock, listen_port, timeout=2.0)
        log_sweep(desc, packet, rtt)
```

### 3.3 `heartbeat` — 纯心跳

只发送心跳帧，不竞争控制：

```python
def heartbeat_profile():
    """仅发送心跳，测量链路延迟基线。"""
    while running:
        packet = build_downlink_packet(
            mode=Mode.HEARTBEAT.value,
            ...
        )
        sock.sendto(packet, (mock_amd_host, mock_amd_port))
        rtt = await_response(sock, listen_port, timeout=2.0)
        log_rtt(packet, rtt)
        time.sleep(1.0)  # 1Hz
```

### 4.2 MCAP 导出（可选）

```bash
python scripts/attacker_station.py --profile conflict --export-mcap log/conflict_test.mcap
```

MCAP 包含：
- `/attacker/ckth` topic: 发送的 $CKTH 原始帧
- `/attacker/auv_response` topic: 收到的 $AUV 原始帧
- `/attacker/rtt` topic: 往返延迟测量

## 6. 与 Mock AMD 的交互

攻击站不修改 Mock AMD 代码，仅作为客户端：

```
正常控制台 ──$CKTH──→ Mock AMD ←──$CKTH── 攻击站
正常控制台 ←──$AUV── Mock AMD ──$AUV──→ 攻击站（如果配置了 listen-port）
```

注意：Mock AMD 默认将 $AUV 发回最后发送 $CKTH 的客户端地址。因此攻击站发帧后可能"抢走"响应。这正是双主竞争测试的核心场景。
