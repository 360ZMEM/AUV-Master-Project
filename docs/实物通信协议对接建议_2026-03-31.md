# 实物通信协议对接建议（2026-03-31）

本文档用于承接当前 Foxglove 展示版布局的下一阶段工作：将目前为仿真与回放准备的显示链路，逐步替换为面向实物 AUV 的真实通信协议输入。

当前目标不是直接实现某一版实物协议，而是先明确后续对接时应保持的技术边界、字段契约、推荐接入位置和联调顺序。你后续可结合实物通信协议文档，把本文件中的“待补协议字段”部分逐项补全。

## 1. 当前状态

当前项目中，Foxglove 导师展示版已经依赖以下几类状态与显示数据：

- 模式字符串：`/auv/control/setpoint.mode`
- 置信度数值：`/auv/sensors/status.confidence`
- 电压数值：`/auv/sensors/status.total_voltage_v`
- 深度误差：`/auv/metrics/depth_error`
- 横向误差的临时替代源：`/auv/state/filtered.pose.pose.position.y`
- 面向展示的格式化文本：
  - `/auv/display/confidence_text`
  - `/auv/display/power_text`

其中需要特别注意两点：

1. 回放链路中的总电压已经来自日志解析，可视为“协议字段已知的最小实现”。
2. 实时链路中的总电压目前还是参数化占位，不是实物真值；后续必须替换为真实协议输入。

## 2. 推荐总体原则

后续对接实物时，建议继续坚持下面这条主线：

**先统一数据契约，再落协议解析，最后调整 Foxglove 展示。**

不要反过来做。也就是说：

- 不要先根据 Foxglove 面板需要临时拼字段。
- 不要让布局生成器直接理解实物协议字节位。
- 不要把协议解析逻辑散落到多个节点里。

推荐分层如下：

1. 协议解析层：把实物通信协议解析成结构化原始状态。
2. ROS 适配层：把协议状态映射成稳定 ROS 话题和消息。
3. 展示派生层：把 Foxglove 需要的文本、误差和演示型指标从稳定 ROS 话题中派生出来。
4. 布局层：只消费稳定话题，不参与任何协议判断。

## 4. 实物协议优先补齐的字段

后续结合实物通信协议，建议优先确认下面这些字段是否存在，以及它们的单位、量纲、更新时间和异常语义。

### 4.1 电压链路

这是当前最应该优先补实物真值的一项。

建议在协议里确认：

- 总电压字段是否存在
- 单位是否为 `V`、`0.1V`、`mV` 或其他缩放格式
- 采样频率和刷新周期
- 低电压阈值是否已有上位机/控制器定义
- 是否还有单节电池电压、母线电压、供电状态位等辅助信息

推荐映射：

- 协议原始字段 -> `SensorStatus.total_voltage_v`
- 阈值判断 -> `SensorStatus.battery_low`
- 展示文本 -> `/auv/display/power_text`

建议不要直接在布局里用阈值判断。阈值判断应在 ROS 层完成。

### 4.2 横向误差链路

当前布局里的 `lateral_error` 只是暂时用 `pose.pose.position.y` 代替。这在演示阶段可以接受，但对接实物时不够严谨。

后续应优先确认协议或导航链路中是否已经存在：

- cross track error
- lateral offset
- path deviation
- cable offset
- 参考线相对偏移

如果协议里没有现成字段，建议在 ROS 层基于以下数据计算：

- 当前估计位置
- 当前参考轨迹或搜索航线
- 当前航向或切向方向

推荐做法：

1. 不在 Foxglove 布局里计算 lateral error。
2. 在控制/导航层或专门的 metrics 节点中计算 lateral error。
3. 发布独立话题，如：`/auv/metrics/lateral_error`。

如果后续补了这个话题，Foxglove 布局应从 `pose.pose.position.y` 切换到真正的 lateral error 话题。

### 4.3 置信度链路

当前 `confidence` 来源于定位协方差的简化映射。这对仿真可用，但对实物场景未必是最终定义。

后续应确认：

- 实物导航系统是否已有定位质量指标
- 是否存在 DVL 锁定状态、GPS 有效位、INS 质量等级、融合状态码
- 是否存在目标识别/跟踪置信度，与定位置信度是否需要区分

推荐策略：

- 如果实物协议已有“导航置信度”，则定义它和现有 `SensorStatus.confidence` 的关系。
- 如果没有，就继续保留当前协方差映射，但要在文档中说明它是“融合估计置信度”，不是“整机任务置信度”。

### 4.4 模式字符串链路

当前布局已经改成直接显示 `/auv/control/setpoint.mode` 的原始字符串。这个方向是对的，后续不要再回到“显示层私自翻译术语”。

后续要确保：

- 行为树输出 mode 与上位机显示 mode 完全一致
- 协议中若存在模式码，应在适配层统一翻译为稳定字符串
- 不同节点不要各自维护一套 mode 文本

推荐约束：

- 实物协议模式码 -> 统一映射到 `Setpoint.mode`
- Foxglove 只显示 `Setpoint.mode`

## 5. 推荐增加的实物指标话题

为避免把所有展示逻辑都压进 `SensorStatus`，建议后续引入一组独立 metrics 话题，用于展示但不干扰决策消息定义。

建议优先考虑：

- `/auv/metrics/depth_error`
- `/auv/metrics/lateral_error`
- `/auv/metrics/heading_error`
- `/auv/metrics/track_progress`
- `/auv/metrics/staleness_sec`

这样做的好处是：

- 决策消息保持稳定
- 可视化指标可单独扩展
- 不会把协议原始字段和演示指标混在一起

## 6. 推荐的展示链路实现方式

当前用于 Foxglove 的两个文字展示话题：

- `/auv/display/confidence_text`
- `/auv/display/power_text`

本质上是“展示派生层”话题，不应被其他控制逻辑依赖。

后续可继续保持这个分工：

- 原始状态话题负责语义正确
- `display/*` 负责格式化、美观和阈值高亮

建议未来如需补更多展示文本，也继续放到同一类命名空间下，例如：

- `/auv/display/mode_banner`
- `/auv/display/alarm_summary`
- `/auv/display/nav_quality_text`

## 8. 推荐实施顺序

建议按下面顺序推进，而不是同时开很多口子：

1. 先把实物协议中的总电压接通，替换 live 链路里的 `nominal_voltage_v` 占位。
2. 再补真正的 lateral error 来源，不再使用 `pose.pose.position.y` 代替。
3. 然后确认 `confidence` 的定义是否要切换到实物导航质量指标。
4. 最后再补更复杂的告警汇总、状态码解释和高级展示文本。

这个顺序的原因很直接：

- 电压是当前展示上最明显的“仿真占位痕迹”
- lateral error 是控制效果展示的核心指标
- confidence 涉及语义定义，改早了容易反复

## 9. 联调验收建议

对接实物协议后，建议至少做下面这些验收项：

### 9.1 字段正确性验收

- 电压在 Foxglove 中与上位机或原始日志一致
- 低电压阈值触发与协议状态一致
- 模式字符串与控制后台输出一致
- 误差曲线与离线分析结果一致

### 9.2 时序验收

- 电压刷新不出现长时间卡死
- 模式切换后 Foxglove 大标题同步刷新
- 控制误差曲线无明显错位或跨 topic 时间漂移

### 9.3 异常工况验收

- 断链后 display 话题能否进入安全降级显示
- 电压字段缺失时是否有明确 fallback
- 协议短时抖动时误差图是否会出现无意义尖峰

## 10. 不建议的做法

后续对接实物时，建议避免下面这些做法：

- 直接在布局 JSON 中硬编码协议字段语义
- 在多个 ROS 节点里各自解析一遍实物协议
- 把“展示字符串”和“控制语义字段”混用
- 用 UI 面板颜色反推控制逻辑状态
- 在没有统一字段文档前，先大规模改布局

## 11. 建议的下一份补充文档

你拿到实物通信协议后，建议继续补一份专门文档，名称可以直接沿用下面这种形式：

- `docs/实物协议字段映射表_YYYY-MM-DD.md`

推荐内容包括：

- 协议帧结构
- 字段偏移与位定义
- 单位与缩放规则
- ROS 映射关系
- 阈值与告警逻辑
- 联调抓包样例

这样后续代码改动时，就不会再出现“代码里知道、文档里没有”或者“文档里写了、显示链路没跟上”的问题。

## 12. 结论

如果只看下一步优先级，当前最值得先补的不是新布局，而是这两项：

1. 用真实协议字段替换 live 链路里的电压占位值。
2. 用真实导航/参考线关系计算 lateral error，并发布独立 metrics 话题。

只要这两项补上，当前导师展示版布局就会从“可演示”明显提升到“可对照实物解释”。
