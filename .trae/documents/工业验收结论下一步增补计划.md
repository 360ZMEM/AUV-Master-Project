# 工业验收结论下一步增补计划

## Summary

本计划接续当前声磁电缆探测 fullflow 的工业验收结论：链路已经打通，DL/T 1278 风格产物可以生成，但工业结论仍应保持 `limited`，原因是证据链还缺少稳定的动态质量指标、埋深不确定度有效比例、多次运行统计、自动 mission 注入和可视化验收面板。

下一步目标不是追求一次报告显示“正常状态”，而是让系统具备可复现的工业验收判断能力：

- 若数据满足阈值，报告可以给出 `industrial_acceptance_pass=true` 与 `industrial_conclusion_readiness=ready`。
- 若 route offset、confidence、burial sigma 或样本量不达标，报告必须清楚保留 `limited/invalid`，并指出失败项。
- 主仓和 `AUV-Master-Mag` 分工清晰：子仓负责磁探测质量、埋深反演和 API 契约；主仓负责 ROS2 集成、仿真复现、DL/T 产物、可视化和文档。

- `tools/plot_cable_tracking_fullflow.py` 已能生成基础 tracking/guidance 图，但没有质量 flags 时间线、confidence/burial sigma 验收图。
- `foxglove_layout_project/config/topics.py` 已注册 `/auv/cable/tracking`、`/auv/cable/diagnostics`、`/auv/cable/dlt1278_summary`。

### 仍然阻止工业验收完善的缺口

主仓缺口：

- `auv_stack.launch.py` 还没有 `enable_cable_mission_autostart` 及 mission 参数，fullflow 仍依赖手动 `ros2 topic pub`。
- `brain_linux/src/auv_control/setup.py` 还没有 mission autostart console entry point。
- 单次 DL/T 报告没有从 CLI 或配置传入验收阈值，不能直接复用 `brain_linux/config/cable_tracking.yaml` 的 `acceptance`。
- 缺少多 run 聚合工具，不能证明指标稳定性。
- Foxglove layout 只展示 cable 基础曲线，缺少工业验收视角的质量摘要和 flags 可见性。
- 文档还停留在上一轮 `limited` 结论，没有记录增补后的验收口径、运行命令和失败解释。

`AUV-Master-Mag` 缺口：

- 当前 `DeploymentQualityEstimator` 仍是轻量质量层，`fit_residual_m` 和 `prior_alignment_residual_m` 主要来自 route projection 代理，还没有和完整 `perception/orchestrator.py` 的 `PerceptionState` 做更深融合。
- `MagneticInput.quality_flags` 暂未进入质量估计逻辑，主仓传感器状态、饱和、标定异常等外部质量信息还不能影响 confidence。
- burial inverter 在短 run 中可能长期 `warming_up`，需要 API 层把 sample_count、warming-up 状态和未成熟原因表达得更稳定。
- 子仓 docs/API 契约需要同步说明 `DeploymentPerceptionConfig`、quality diagnostics 和主仓消费字段。

## Assumptions & Decisions

- 不把 `AUV-Master-Mag` 内部 demo/main 流程改成依赖主仓；子仓只增强 public API 和文档。
- 不在主仓重写磁探测算法；主仓只配置、调用、透传和验收 `AUV-Master-Mag` 输出。
- `ready` 是证据链状态，不等于真实世界最终验收证书；真实验收仍需要实测标定、外部资产信息和人工签核。
- 当前已有旧 fullflow 结果保留为 limited 基线，不覆盖、不删除。
- 如果新 run 仍然 route offset 超限，工作目标是让系统准确报告超限原因，而不是调低阈值制造通过。
