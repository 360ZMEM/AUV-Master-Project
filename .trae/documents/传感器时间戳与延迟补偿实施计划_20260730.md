# 传感器时间戳与延迟补偿实施计划（2026-07-30）

## 1. 审计结论

- VxWorks `$AUV` 上行原始协议没有独立传感器源时标；此前新增的 Para3 只表示 PC104 组包相对时间，Para12 为有效 marker。
- DVL 是低频速度观测，真实解析时间可能早于 `$AUV` 组包时间；需要单独记录 DVL BI 最近解析时刻。
- IMU 与深度当前仍随 `$AUV` 同帧上行。IMU 可先使用组包时间；深度话题仍为 `std_msgs/Float32`，无法直接承载 header。
- Jetson 侧 `fangkong_adc` 已有 `LatestSnapshot.timestamp`，表示 ADC 批次在 wrapper 管线中的处理/快照时间；原磁传 wrapper 使用 ROS 发布时刻，存在可补偿的发布延迟。
- 前视声呐 wrapper 当前发布 `std_msgs/Float32`，属于低频地形输入，本轮不破坏兼容；后续迁移到 stamped topic。

## 2. 本轮补偿范围

- 必须补偿：
  - VxWorks DVL BI：Para4 承载最近 DVL BI 解析 PC104 uptime。
  - protocol_udp 仿真：Para3/Para4/Para12 字段完整生成，验证消息层消费。
  - brain_linux bridge：IMU 使用 Para3，DVL 优先使用 Para4，旧固件回退 Para3/收包时刻。
  - localization/ES-EKF：predict 使用 IMU header stamp 增量；DVL world-frame correction 使用 DVL stamp 做延迟噪声膨胀。
  - Jetson 磁传：`MagneticField.header.stamp` 使用 `fangkong_adc` snapshot timestamp。
- 暂不操作：
  - 深度 `Float32`：保持兼容，继续用 IMU 时间作为 localization 参考。
  - 前视声呐 `Float32`：低频地形输入，后续单独迁移 stamped topic。
  - ADC 硬件级采样时钟：当前无硬件时间戳，只能用 wrapper snapshot 时间；后续如 FK2301 提供采样计数，再做硬件时钟映射。

## 3. 链路延迟测试

1. protocol_udp 仿真：
   - 解析 `$AUV` 原始包，确认 Para3、Para4、Para12 字节位置正确。
   - 订阅 `/auv/sensors/imu` 与 `/auv/sensors/dvl`，记录 `now - header.stamp`。
   - 人为降低 DVL 采样频率，确认 DVL stamp 不晚于 IMU stamp。
2. VxWorks 实物：
   - Telnet 注入或开启 DVL BI 数据输入，抓取 PC104 上行 UDP。
   - 校验 Para12 为 `0x5453`，Para3 单调增加，Para4 在 DVL 更新时变化且不大于 Para3。
   - 断开 DVL 后确认 Para4 保持最近值，Jetson 不崩溃。
3. Jetson 磁传：
   - 记录 `fangkong_adc` snapshot timestamp 与 `/auv/sensors/magnetic.header.stamp`。
   - 统计 ROS 发布时刻减 header stamp，得到 wrapper 管线延迟。

链路延迟采集与绘图基建：

```bash
python3 tools/plot_link_latency.py collect \
```

- `link_latency_timeseries.png`：链路延迟折线图。
- `link_latency_distribution.png`：链路延迟分布图。

## 4. 补偿有效性测试

1. 单元测试：
   - 协议字段 roundtrip：Para3/Para4/Para12。
   - PC104 uptime 到 ROS time domain 映射，含 DVL 源时标早于组包时标。
   - ES-EKF world-frame DVL timestamp correction：延迟超过 50 ms 时噪声增大。
2. 仿真冒烟：
   - 启动 protocol_udp backend。
   - 验证 IMU/DVL header stamp 可被 localization 消费。
   - 验证 localization predict dt 来源于 IMU stamp，而不是 wall-clock timer。
3. A/B 对比：
   - A：禁用 Para4 或使用旧固件回退。
   - B：启用 Para4 与 timestamp-aware DVL correction。
   - 对比速度残差、NIS、深度/横向误差、DVL 延迟统计。

## 5. 实物测试顺序

1. probe：只抓 UDP 原始包，不启动完整 ROS stack。
2. headless：启动 bridge，订阅 IMU/DVL/magnetic，检查 header stamp 与延迟统计。
3. wrapper smoke：单独启动 `magnetic_sensor_wrapper_node`，确认不会生成 `data/` 且 stamp 来自 ADC snapshot。
4. stack smoke：启动完整 brain_linux，确认 localization 状态连续、停机无竞态报错。

## 6. 验收标准

- 新固件 `$AUV` 帧 Para12 固定为 `0x5453`。
- Para3 为 PC104 组包相对 uptime，Para4 为 DVL BI 最近解析 uptime。
- 旧固件或 marker 缺失时，Jetson 自动回退，不影响现有链路。
- DVL `TwistStamped.header.stamp` 可早于同帧 IMU stamp，localization 使用该时间做延迟噪声膨胀。
- 磁传 `MagneticField.header.stamp` 使用 ADC snapshot timestamp；mock 模式仍使用发布时刻。
