## 1. 总则与硬约束

### 1.1 权威源与只读参考

- **规则**：LaTeX 源（`thuthesis/data/auv-*.tex`）是唯一权威事实源；`docs/thesis/paper/*.md` 等 Markdown 为**只读历史参考**，不得据其反推或回改 LaTeX。
- **理由**：LaTeX 已超前于 canonical Markdown（前向引用、符号、`\texttt` 迁移均在 LaTeX 扩写阶段引入），二次同步会造成漂移。
- **来源**：`毕业设计写作文档/潜在待完成事项/23_全文超前叙述_命名残留_AI味_MD-LaTeX映射审计.md` §5.1「LaTeX 是当前事实源且已超前于 canonical md」。

### 1.2 不可更改口径

- **规则**：不改实验数值、不改结论、不改图像口径。表格显示位数统一时若会改变呈现值，则保留原值不动并记录。
- **理由**：写作层审计只做叙述、排版、编号、引用的规范化，绝不触碰计量结论。
- **来源**：`.trae/documents/ThuThesis全文质量提升审计计划_20260824.md` 表格规范第 3 条（「不做四舍五入改值，只统一显示位数」）。

### 1.3 编译门控

- **规则**：每章改后先单独编译（`xelatex` 该章无 undefined ref）；整册 `make auv-thesis` 必须 **0 undefined ref / 0 multiply-defined / 0 Overfull / 0 未定义引文**。图像审计另有 0 warning 要求。
- **理由**：这是 R31 静态门控与全文质量提升 pass 的验收基线；当前已达成（191 页）。
- **来源**：`.trae/documents/ThuThesis全文质量提升审计计划_20260824.md` §CP 验收列；`ThuThesis全量图片统一与可复现审计计划.md` 成功标准。

### 1.4 平台分流

- **规则**：Darwin（本机）侧只做写作、排版、检索、图像重绘与来源核验，**不碰 ROS/仿真/实物代码**；需要真机采集/ROS2 重绘的图（如 mag_chain_noise_ros、terrain 相关 MCAP）在 Linux 侧完成。
- **理由**：`uname` 返回 Darwin 即写作职责；ROS2 环境仅在 Linux 侧。
- **来源**：仓库根 `AGENTS.md` 分流约定；图像契约中标注的「Linux/ROS2 必须完成的边界」。

### 1.5 正文禁 TODO

- **规则**：正文（含表格、caption）不得出现 `TODO`、`补模型`、`补偏差表` 之类占位标记。未完成事项写入 `毕业设计写作文档/潜在待完成事项/` 或附录成果清单，不污染正文。
- **理由**：静态门控优先级高于任何图文压缩；曾在 chap02 §2.4.1/§2.5.1 残留 TODO 被清除。
- **来源**：`毕业设计写作文档/潜在待完成事项/21_thuthesis阶段性写作审计计划与报告.md` §3.2。

## 2. 公式规范

### 2.1 一律编号

- **规则**：所有展示公式使用 `equation`（多行用 `equation` 内嵌 `aligned/cases/bmatrix` 或 `align`）并配 `\label`。**禁 `\[...\]` 裸公式、禁 `equation*`、禁 `\nonumber` 抑制编号**。
- **理由**：可答辩、可引用、可复核；全文已将 `\[...\]` 归零。当前各文件 `equation` 数：chap02=21、chap03=20、chap04=16、chap05=6、附录 A=16。
- **正例**：`thuthesis/data/auv-chap04.tex:20` `\begin{equation}\label{eq:ch04-state-vector}...\end{equation}`。
- **反例**：`\[ J = J_1 + J_2 \]` 裸公式（已全部转换）。
- **来源**：`ThuThesis全文质量提升审计计划_20260824.md` §CP1 执行记录（L144–146）。

### 2.2 label 命名风格

- **规则**：label 统一 `eq:chNN-语义`（如 `eq:ch04-cost-decomposition`、`eq:ch04-cbf-decay`）；附录用 `eq:app-a-*`。语义化，不用序号。
- **理由**：沿用 chap04 既有命名风格，跨章一致、便于检索。
- **来源**：`thuthesis/data/auv-chap04.tex` 全部 `\label{eq:ch04-...}`。

### 2.3 正文指代口径

- **规则**：正文指代公式统一用 `式\eqref{eq:chNN-xxx}`（ThuThesis 类渲染为「式(x.y)」）。禁止「该式/上式/式中/如下式/由此可得」等无编号指代残留。
- **理由**：thuthesis.cls 已提供 `\eqref`，官方示例即 `式\eqref{eq:...}`。
- **正例**：`thuthesis/data/auv-chap04.tex:175` 「式\eqref{eq:ch04-guaranteed-coverage}把……」。
- **来源**：`ThuThesis全文质量提升审计计划_20260824.md` §CP1（L48、L100）。

### 2.4 一次性代入式例外

- **规则**：纯一次性数值代入的中间式（如 `Δx = v·τ = 0.2 m`，chap03 早期位置）在上下文无指代时可不编号。
- **理由**：这类是行内演算而非需被引用的结论式，强制编号反增噪声。
- **来源**：`ThuThesis全文质量提升审计计划_20260824.md` §2.3 C 例外（L101）。

### 2.5 符号语义唯一

- **规则**：一个符号在全文语义唯一；数值域冲突必须区分记号。已落地：CBF 衰减系数用 `\alpha_{\mathrm{cbf}}`（`eq:ch04-cbf-decay`），与置信度幂指数 `\alpha`（`\rho(c)=(1-c)^\alpha`）区分，并在正文加一句独立参数说明。
- **理由**：α 曾一符两义（幂指数取 1.5 vs CBF 衰减 0<α≤1），数值域冲突。
- **正例**：`thuthesis/data/auv-chap04.tex:432`「此处的衰减系数 \(\alpha_{\mathrm{cbf}}\) 与式\eqref{eq:ch04-confidence-weight}中的置信度幂指数 \(\alpha\) 是两个独立参数」。
- **来源**：`23_...AI味_MD-LaTeX映射审计.md` §7.4 修复项；审计计划 L240、L304。

### 2.6 跨文件符号桥接

- **规则**：跨文件同名符号必须桥接说明，避免撞名。已落地：正文 `s_u(c)` 与附录控制增量权重的关系补 `w_u(c)=w_{u,0} s_u(c)`。先用后定义处补「定义见 §4.4.3」。
- **理由**：`w_u` 曾在正文（surge 速度跟踪权重）与附录（控制增量权重）撞名；`c` 曾先用后定义。
- **来源**：审计计划 L241、L244、L309。

### 2.7 代价函数口径

- **规则**：MPC 代价函数分解为 `J = J_tracking + J_control + J_terminal`；控制代价惩罚指令**增量 Δu** 而非幅值（`J_control = Σ s_u(c)(W·Δψ² + W·Δz² + W·ΔT²)`），终端项 `J_terminal = e_N^T Q_f e_N`。叙述须解释「惩罚增量抑抖动不偏置稳态、终端项改善有限时域收敛」，并与「控制变化率下降」的实验叙述对齐。
- **理由**：口径与附录及实验结论一致，避免方法—结果脱节。
- **来源**：审计计划 L308；`thuthesis/data/auv-chap04.tex:276/289/301`（`eq:ch04-cost-decomposition/tracking-cost/control-cost`）。

## 3. 交叉引用规范

### 3.1 统一「节」引用样式

- **规则**：节引用统一 `第~\ref{sec:chNN-x-y}节` 样式；章/图/表引用用 `第 N 章`、`图~\ref{}`、`表~\ref{}`。**避免 `§`、`\S`、纯数字「x.y 节」混用**。
- **理由**：全文统一样式便于阅读与答辩。当前正文主体已统一为 `第~\ref{sec:}节`。
- **注意**：chap02/chap03 仍残留 5 处 `§`（见 §10 待裁决）。
- **来源**：`ThuThesis全文质量提升审计计划_20260824.md` §2.4 C（L109）。

### 3.2 抑制过度回指

- **规则**：对同一后置总表/边界节，保留每条主线**首次**指向的引用，重复段落改为集中指针或删除冗余，避免每段都跳到同一目标。
- **理由**：`sec:ch05-5-6` 曾被引 16 次、`sec:ch05-5-3-1` 13 次；已收敛到 8/9 次，不丢可追溯性。
- **来源**：审计计划 §CP2（L107、L150）。

### 3.3 前引仅限路线图式预告

- **规则**：前文对后章的引用只能是「路线图式预告」（如「其系统级实测验证属实验章内容」），**禁止「结论依赖尚未出现的实验」**。前引弱化到章级（`实验章`/`第 5 章`），删除具体后章小节号与跨章图表 `\ref`。
- **理由**：绪论曾提前引用「本文的实验结果」、chap04 曾跨章 `\ref` chap05 的表/图，属非预期前引。
- **正例**：chap04 已把「见表~\ref{tab:ch05-...}及图~\ref{fig:ch05-...}」改为「统一收纳于实验章」。
- **来源**：`23_...AI味_MD-LaTeX映射审计.md` §1.4/§6.1（用户 2026-08-13 决策：弱化章号、删跨章结果 `\ref`、错标 label 必修）；审计计划 L57、L108。

### 3.4 先定义后引用

- **规则**：概念/符号先定义再引用；同章「先总后分」的后节引用可接受，但须确认被引对象已定义。
- **理由**：`c` 先用后定义已修复，是此规则的直接来源。
- **来源**：`23_...` §2.4；审计计划 L244。

## 4. 表格规范

### 4.1 单位上提表头

- **规则**：列内单位同质时，单位抽到列标题（如「水平 RMSE（m）」「p95（ms）」），数据格只留数字与 `±`。异质单位行（如标定表 m/°/% 混排、传感器速率表）单位保留在格内。
- **理由**：数据格 `2.97±1.41 m` 混排单位可读性差。已落地：ESKF 多扰动表、地形三档消融表、MPC 极端路径表、长时程相位表、杆臂校正表、原生因子闭环全矩阵表均已上提，数值一字未改。
- **来源**：审计计划 §2.2 第 1 条（L88）、§CP4 执行记录（L163）。

### 4.2 折叠 pandoc minipage 表头

- **规则**：pandoc 生成的 `\begin{minipage}[b]{\linewidth}\raggedright ... \end{minipage}` 表头折叠为普通 `>{\raggedright\arraybackslash}p{}` 列头，删除逐格 minipage。**子图用的 `[t]{0.49\linewidth}` minipage 不要误伤**。
- **理由**：逐格 minipage 使单元格垂直堆叠、可读性差。已折叠 188 处（chap01=10/chap02=62/chap03=16/chap04=18/chap05=74/附录=8），无残留。
- **来源**：审计计划 §2.2 第 2 条（L89）、§CP4（L161）。

### 4.3 清理 `\allowbreak{}` 噪声

- **规则**：列宽足够时移除人工断行 `\allowbreak{}`，`\allowbreak{}±` 还原为 `±`。窄列引脚名（如 `\texttt{Trig1 / Trig GND}`）内为断行需要可保留。
- **理由**：pandoc 遗留噪声。
- **来源**：审计计划 §CP4（L162）。

### 4.4 有效数字位数统一

- **规则**：同类量在同表/同族表内小数位一致（RMSE 两位、比率三位、覆盖率三位等，取现有多数口径）。**只统一显示位数，不做四舍五入改值**；若显示位数变化会改变呈现值，则保留原值并记录。
- **来源**：审计计划 §2.2 第 3 条（L90）。

### 4.5 表头术语统一 + longtable

- **规则**：跨表术语一致（「成功/总数」「95% 带覆盖率」「上界超限率」等）；跨页 longtable 确认 `\endfirsthead/\endhead` 不重复。表格环境优先 `booktabs` + `threeparttable`（`auvsetup.tex` 已加载）。
- **来源**：审计计划 §2.2 第 5/6 条（L92、L93）；`thuthesis/auvsetup.tex:23-26`（threeparttable/multirow/tabularx/longtable）。

## 5. 标识符去泄露规范

### 5.1 判定原则（核心）

- **规则**：区分两类标识符——
  - **接口契约（保留 `\texttt{}`）**：协议帧（`$CKTH`/`$AUV`）、ROS 话题（`/auv/control/mpc_cmd`、`/auv/cable/dlt1278_state`）、十六进制命令字（`0xEE`、`0x01`）、寄存器/状态机常量（`Solve_Succeeded`）、硬件接口标识（IP 段 `192.9.0.X`、`Trig1`、`+Vdc`）。
  - **工程内部记号（正文去除/叙述化）**：内部实验批次代号（R13/R18/R19/R22、P-1/P-2、H4）、Python 脚本名、仓库相对路径、commit/SHA256/条目 ID。
- **理由**：接口契约是读者理解系统所需的技术事实；内部记号只服务开发定位，对论证无解释力。
- **来源**：审计计划 §1.1 判定原则（L30）；`23_...` §6.1 用户决策（「硬件接口标识保留」「数学符号+命名全清」）。

### 5.2 内部代号叙述化

- **规则**：内部代号全部替换为描述性名称（如 R18→「五分钟长时程观测相位实验」，R13/R13-v2→「不确定性感知控制代理场景实验」）；代号仅在**附录成果清单**保留可追溯映射（`\label`/`\ref` 键不受影响）。
- **理由**：正文 grep 代号已归零；答辩读者无需知道内部批次号。
- **来源**：审计计划 §2.1 A 代号替换表（L66–79）、§CP3（L155）。

### 5.3 裸路径/脚本叙述化

- **规则**：裸脚本名/路径叙述化（`run.sh`→「一键复现脚本」，`decoupled_cable_sim_node.py`→「解耦电缆仿真节点」，`hardware_wrappers/fangkong_adc/raw_data`→「方控 ADC 原始记录目录」）。确需给出路径处移入脚注或附录成果清单，且与清单一致。`\includegraphics{}` 内的构建期资源路径（读者不可见）保留。
- **来源**：审计计划 §2.1 B（L81）、§CP3（L156）。

### 5.4 附录自洽

- **规则**：附录若自述「不保留实现定位信息」，则内容须与之一致（不得又列出脚本名/SHA256/路径作为正文可见信息）。
- **理由**：避免附录声明与内容矛盾。
- **来源**：审计计划标识符去泄露主线的一致性要求（§1.1）。
