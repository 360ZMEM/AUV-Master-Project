# 深度安全多层围栏 — 最小修复计划

## 一、总体目标

根据 AI 架构师的安全审计结论，对 VxWorks 底盘固件和 Jetson 控制代码进行最小侵入修复，建立 **VxWorks 被动防御 + Jetson 主动规避** 的双层安全围栏体系。

---

## 四、详细修改方案

### 4.1 BUG-1 修复：舵机步进值防御性限幅

**文件**: `csd_vx6.8_lastest/main.c`  
**位置**: `Jetson_Shadow_Proces()` 函数（第511-529行）

**修改内容**:  
在 PID 输出赋值到 `(u16)` 之前，增加防御性硬限幅。虽然 PID 内部已有 ±20° 限幅，但作为 defense-in-depth，需在类型转换前再次钳位，防止 NaN、未初始化、或算法异常导致的溢出。

```c
/* 防御性限幅: 防止 NaN 或异常值导致 u16 溢出 (defense-in-depth) */
if(course_pid_output < -20.0f) course_pid_output = -20.0f;
if(course_pid_output >  20.0f) course_pid_output =  20.0f;

Instruction_To_FMCU.McuFD_UV_Set_Rud_Location = (u16)(UV_Ref_Location - course_pid_output * 4096/360);
Instruction_To_FMCU.McuFD_LV_Set_Rud_Location = (u16)(LV_Ref_Location + course_pid_output * 4096/360);

/* 防御性限幅: depth_pid_output */
if(depth_pid_output < -20.0f) depth_pid_output = -20.0f;
if(depth_pid_output >  20.0f) depth_pid_output =  20.0f;

Instruction_To_FMCU.McuFD_LH_Set_Rud_Location = (u16)(LH_Ref_Location - depth_pid_output * 4096/360);
Instruction_To_FMCU.McuFD_RH_Set_Rud_Location = (u16)(RH_Ref_Location + depth_pid_output * 4096/360);
```

**同时增加 NaN 检测**（VxWorks 6.8 可用 `isnan()` 宏）:
```c
/* NaN 异常检测: 如果 PID 输出为 NaN, 强制归零 (传感器故障防御) */
if(course_pid_output != course_pid_output) course_pid_output = 0.0f; /* NaN != NaN */
if(depth_pid_output != depth_pid_output) depth_pid_output = 0.0f;
```

### 4.2 BUG-3 修复：深度超限计数器增加递减/自恢复

**文件**: `csd_vx6.8_lastest/SecurityEmergencyManage.c`  
**位置**: `EmergencyTask()` 第92-105行

**修改内容**: 当深度回到安全范围时，计数器递减（而非保持不变）。增加 `else` 分支实现滑动窗口式防抖。

```c
/* 深度超限保护参数1: 滑动窗口防抖 (解决只增不减闩锁bug) */
if((Current_State.Current_Dep > UI_WIFI_Instruction.FromUI12_Depth_Para1) 
   && (UI_WIFI_Instruction.FromUI12_Depth_Para1 != 0))
{
    Depth_Exceed_FromUI12_Depth_Para1++;
}
else
{
    /* 深度回到安全范围时递减, 允许系统自恢复 */
    if(Depth_Exceed_FromUI12_Depth_Para1 > 0) Depth_Exceed_FromUI12_Depth_Para1--;
}
```

同样对 `Depth_Exceed_FromUI12_Depth_Para2` 做相同处理。

### 4.3 BUG-4 修复：超深保护改为"维持舵效+打满上浮舵"

**文件**: `csd_vx6.8_lastest/SecurityEmergencyManage.c`  
**位置**: 深度超限 Para1 触发后的动作代码（第99-105行）

**修改内容**: 将"推力归零"改为"保持最低舵效航速 + 打满上浮舵"，让欠驱动 AUV 能靠水平舵产生升力上浮。

```c
if(Depth_Exceed_FromUI12_Depth_Para1 >= 10)
{
    Sys_Abnorm_Inf_Judgement |= 0x00000200;
    
    /* 
     * [修复] 欠驱动AUV超深自救: 保持最低舵效航速, 打满上浮舵
     * 旧逻辑(致命bug): Motor_Speed1=0 导致失去舵效直接沉底
     */
    Instruction_To_FMCU.McuFD_Motor1_Set_Speed = 300;  /* 最低舵效航速 ~2节 */
    
    /* 打满上浮舵 (-20度) */
    Instruction_To_FMCU.McuFD_LH_Set_Rud_Location = 
        (u16)(LH_Ref_Location - (-20.0f) * 4096/360);
    Instruction_To_FMCU.McuFD_RH_Set_Rud_Location = 
        (u16)(RH_Ref_Location + (-20.0f) * 4096/360);
    
    Remote_Assignment(&Instruction_To_FMCU);
}
```

> **注意**: Para2 触发（更严重级别）保留 `EL_Power_Control(Power_ON)` 应急压载逻辑不变，但同样将推力改为 300 + 上浮舵。

### 4.4 BUG-5 修复：新增 `Seafloor_Grounding_Arbitration()` 离底高度硬栅栏

**文件**: `csd_vx6.8_lastest/SecurityEmergencyManage.c`  
**位置**: 文件末尾新增函数

**调用点**: 在 `EmergencyTask` 的 `FOREVER` 循环中（semTake 成功后）调用

**实现要点**:

1. 读取 `DVL_Prase_Data.BD_Check` 判断底锁有效性（== 2.0 或 3.0）
2. DVL 未锁底时：清除高度告警，由深度限幅接管（return）
3. 滑动窗口防抖：`altitude_warning_count` / `altitude_critical_count` 双计数器（递增+递减）
4. 软限(3.0m) 持续 0.5s：置告警位 + 强制限死目标深度不允许更深
5. 硬限(1.8m) 持续 0.3s：**强制夺权**调用 `HightCtrlAlgorithm(4.0, ...)` 拉起 + 限制推力 350RPM

**参数设计依据**:
- 3.0m 软限: AUV 3节巡航速度下拉起弧度约 1.0-1.5m，留出 1.2m 缓冲
- 1.8m 硬限: 防止礁石/渔网缠绕的物理极限
- 4.0m 拉起目标: 声呐最佳工作高度

### 4.5 BUG-6 修复：DVL 丢底自救保护

**文件**: `csd_vx6.8_lastest/SecurityEmergencyManage.c`  
**位置**: 嵌入 `Seafloor_Grounding_Arbitration()` 函数内部

**实现要点**:

1. 新增静态计数器 `dvl_lost_lock_count`
2. DVL 未锁底时递增；锁底时清零
3. 持续丢底 2.0s（≥20 ticks）且处于 0xEE/0xEF 模式时触发：
   - 模式降级至 Remote(0x01)
   - 调用 `DepthCtrlAlgorithm(2.0, ...)` 定深上浮至 2m 安全层
   - 保持低速 300RPM 航行
4. 非自主模式下丢底不主动介入（遥控模式由操作员判断）

### 4.6 BUG-7 修复：水池测试安全模式

**文件**: `csd_vx6.8_lastest/main.h` + `SecurityEmergencyManage.c`

**`main.h` 新增**:
```c
/**
 * @brief 水池测试模式开关 (编译时常量)
 * 0 = 海试模式 (soft_limit=3.0m, hard_limit=1.8m)
 * 1 = 水池模式 (深度围栏0.9m + Pitch±10° + Roll±20° + 转速200RPM)
 */
#define POOL_TEST_MODE  0
```

**`SecurityEmergencyManage.c` 新增** `Pool_Safety_Check()` 函数:

在 `EmergencyTask` 循环最前方（优先级最高）调用：

```c
if(POOL_TEST_MODE)
{
    Pool_Safety_Check();  /* 水池模式优先于一切安全逻辑 */
}
else
{
    Seafloor_Grounding_Arbitration();  /* 海试模式离底高度仲裁 */
}
```

`Pool_Safety_Check()` 实现：
1. 深度硬围栏：`Current_Dep > 0.9m` → 推力归零 + 打满上浮舵
2. Pitch 极限截断：`|Pitch| > 10°` → 推力归零
3. Roll 翻转保护：`|Roll| > 20°` → 推力归零
4. 极速限幅：`Motor_Speed > 200` → 钳位到 200

水池模式下离底高度参数自动覆盖：`hard_limit=0.4m, soft_limit=0.8m`

### 4.7 BUG-8 修复：Jetson 端全局深度硬围栏

**文件**: `brain_linux/src/auv_controller/auv_controller/auv_controller_node.py`  
**位置**: 控制输出计算之后、发布命令之前

**修改内容**: 增加全模式通用的深度/高度安全围栏（不仅限于 ALTITUDE_FOLLOW 模式）

```python
# === 全局深度安全围栏 (所有模式通用) ===
MAX_DEPTH_M = 50.0   # 最大允许深度
MIN_ALTITUDE_M = 2.0  # 最小允许离底高度 (与VxWorks软限协调)

# 1. 深度绝对上限
if sp.target_depth_m > MAX_DEPTH_M:
    sp.target_depth_m = MAX_DEPTH_M

# 2. 离底高度围栏 (当altitude有效且不在ALTITUDE_FOLLOW模式时)
current_altitude = self._terrain_perception.get_altitude()
if (not is_altitude_follow 
    and current_altitude > 0.01 
    and current_altitude < MIN_ALTITUDE_M):
    # 强制将目标深度设为当前深度-1m (紧急上浮)
    current_depth = float(-st.pose.pose.position.z)
    sp.target_depth_m = min(sp.target_depth_m, current_depth - 1.0)
```

**与 VxWorks 协调关系**:
- Jetson 软围栏 2.0m（主动避免接近底部）
- VxWorks 软限 3.0m（警告 + 锁深）
- VxWorks 硬限 1.8m（强制夺权拉起）

形成 **Jetson 预防 → VxWorks 警告 → VxWorks 夺权** 的三级递进防线。

## 五、Bumpless Transfer 确认（BUG-2：无需修改）

经代码审计确认，Jetson 侧已在 `auv_controller_node.py` 第440-446行实现完整的 Bumpless Transfer：
- 非自主模式下持续将 `target_depth_m = 当前深度`、`target_heading_rad = 当前航向`（Setpoint Shadowing）
- 模式切换时调用 `reset()` 清除所有积分项

VxWorks 侧 `Course_Keep_Integral_Reset()` / `Depth_Ctrl_Integral_Reset()` 作为空函数预留，因 PD 控制器无积分项，不影响安全。

**结论**: 此项不需要代码修改。

## 六、假设与决策

| 决策 | 理由 |
|------|------|
| `POOL_TEST_MODE` 使用编译时宏而非运行时变量 | 安全关键参数不应在运行时被意外修改；切换需重新编译+下载 |
| 水池深度围栏 0.9m（而非审计建议的 1.0m） | 1.5m 池深 - AUV 自身直径 0.3m - 0.3m 安全余量 = 0.9m |
| DVL 丢底触发阈值 2.0s（20 ticks） | 短于 Jetson 看门狗（1.0s），但 DVL 数据率较低（~4Hz），需要更长窗口过滤 |
| 超深上浮用 300RPM 而非 350RPM | 保守航速约 1.5 节，足以维持舵效但不会产生过大动能 |
| Jetson 侧 MIN_ALTITUDE_M=2.0m | 高于 VxWorks 硬限 1.8m，确保 Jetson 先行规避，减少 VxWorks 夺权频率 |
